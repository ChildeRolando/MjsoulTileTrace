# 雀魂手摸切牌河遮罩设计

日期：2026-07-30
状态：已由用户确认

## 1. 目标

开发一个面向 Windows 雀魂 Steam/桌面客户端的纯离线辅助程序。在四人麻将即时对局中，程序持续观察四家公开可见的牌桌结构变化，并在牌河上显示：

- 摸切牌：使用半透明灰色遮罩压暗。
- 手切牌：使用金色外框与轻微光晕高亮。
- 无法可靠判断的牌：保持游戏原样，不显示遮罩。

遮罩在一局内持续保留；弃牌被鸣走、本局结束、整场结束或识别失去同步时，及时移除相应遮罩。

## 2. 边界

### 2.1 首版范围

- Windows Steam/桌面客户端。
- 四人麻将牌桌。
- 1920×1080 分辨率、100% Windows 显示缩放。
- 固定的雀魂窗口大小和首版支持的标准牌桌布局。
- 四家手牌、独立摸牌槽、牌河和副露区域的实时结构检测。
- 摸切、手切、吃、碰、大明杠、暗杠、加杠、岭上摸牌、弃牌被鸣和局间重置。
- 独立透明、置顶、鼠标点击穿透的牌河遮罩。
- 完全本地运行；不联网、不上传牌谱或画面。

### 2.2 明确不做

- 不注入雀魂进程。
- 不读取客户端内存或内部对象。
- 不抓取、解析或修改网络通信。
- 不模拟鼠标、键盘或其他游戏操作。
- 不提供自动打牌、出牌建议、牌效分析或决策推荐。
- 不设计反检测、规避封禁或绕过反作弊的功能。
- 不保证官方一定允许该工具；发布前仍需核对当时有效的服务条款。
- 首版不支持三人麻将、任意分辨率、任意窗口比例或所有桌布与牌背组合。

## 3. 设计原则

1. **观察结构，不学习动画。** 系统只关心牌桌槽位是否被占用以及数量如何变化，不识别具体出牌特效或运动轨迹。
2. **四家视觉模型独立。** 四家只共享检测接口和事件状态机，不共享尺寸、角度、透视或槽位 pattern。
3. **组合事件优先。** 不以单帧或单一区域变化下结论；在短暂事务窗口内汇总手牌、摸牌槽、牌河和副露变化。
4. **宁缺毋滥。** 低置信度、信号冲突或失去同步时不着色，不能靠猜测提高覆盖率。
5. **遮罩跟随真实牌块。** 牌河记录绑定当前检测到的四边形，而不是只绑定一个理论上的固定格位。

## 4. 总体架构

```text
雀魂目标窗口
    ↓
Windows Graphics Capture
    ↓
牌桌与对局生命周期检测
    ↓
四套 SeatProfile 区域检测器
    ↓
每家槽位占用与数量观测
    ↓
短时间事务聚合器
    ↓
四家事件状态机
    ↓
牌河牌块追踪与事件关联
    ↓
透明点击穿透遮罩
```

程序是独立的 Windows 托盘应用。它自动寻找雀魂桌面客户端窗口，捕获该窗口画面，并创建一个跟随客户端位置和尺寸的透明遮罩窗口。遮罩只绘图，不接收鼠标或键盘输入。

推荐实现栈：

- C# / .NET 8
- Windows Graphics Capture
- OpenCvSharp
- 原生 Windows 透明窗口与扩展窗口样式

Python 可用于离线视觉实验，但不进入最终实时运行链路。

## 5. 四家独立视觉配置

每家拥有独立的 `SeatProfile`。共享代码通过该配置读取不同的视觉模型，而不是复用一张模板。

每份配置至少包含：

- 座位标识：自家、对家、左家、右家。
- 手牌主体区域及其方向。
- 独立摸牌槽区域。
- 理论手牌槽多边形列表。
- 牌河搜索区域、行方向和预期牌块尺度。
- 副露区域及其展开方向。
- 牌块宽高范围、角度范围和透视容差。
- 各区域独立的占用阈值与稳定阈值。

自家牌最大且正向排列；对家较小且方向相反；左右家分别旋转并具有不同透视压缩。因此四家标定数据完全独立，只有输出观测的格式一致。

## 6. 观测模型

每个稳定帧为每家产生一份 `SeatObservation`：

```text
主体手牌张数
主体各槽位占用状态
独立摸牌槽占用状态
副露组数
副露牌张数
自己牌河可见牌块集合
其他三家牌河可见牌块集合
画面稳定度
观测置信度
时间戳
```

识别层只判断槽位或区域中是否存在牌块，不要求识别牌的花色和数字。检测依据以轮廓、边缘、局部前景变化、牌块尺度和空间排列为主。

## 7. 事务聚合与事件分类

动画或重排过程中会出现短暂的中间画面。系统不会立即解释单帧变化，而会打开一个短时间事务窗口，持续收集变化，直到相关区域重新稳定或超时。

事务输入为：

```text
Δ主体手牌
Δ独立摸牌槽
Δ自己牌河
Δ其他三家牌河
Δ副露组
Δ副露牌张
各变化的先后顺序与置信度
```

主要稳定变化及其分类：

| 稳定变化 | 分类 |
|---|---|
| 独立摸牌槽由空变为占用 | 普通摸牌 |
| 摸牌槽占用消失、自己牌河增加，主体没有手切证据 | 摸切 |
| 主体手牌出现移除证据并重排、摸牌槽并入主体、自己牌河增加 | 手切 |
| 手牌减少 2 张、副露增加 3 张、另一家牌河减少 1 张 | 吃或碰 |
| 手牌减少 3 张、副露增加 4 张、另一家牌河减少 1 张 | 大明杠 |
| 手牌减少 4 张、副露增加 4 张、牌河不减少 | 暗杠 |
| 手牌减少 1 张、已有副露由 3 张变为 4 张 | 加杠 |
| 杠后摸牌槽增加 | 岭上摸牌 |

上表描述的是逻辑净变化。实际界面可能分多帧完成，分类器必须用事务内的累计变化和事件顺序匹配。

吃碰后的强制弃牌属于下一笔独立事务。杠操作完成后，系统等待岭上摸牌，再按普通弃牌逻辑判断之后的手切或摸切。

若多个分类同时成立、观测数量不完整、事务超时或置信度不足，则将该事务标记为未知，不产生新的牌河着色。

## 8. 牌河追踪

每张已确认的新弃牌创建一条 `RiverTile`：

```text
唯一 ID
座位
首次出现时间
当前四边形
摸切 / 手切 / 未知
正常 / 被鸣走
追踪置信度
```

每帧在各家的独立牌河区域内检测可见牌块，并使用以下条件与上一帧记录匹配：

- 四边形重叠比例。
- 中心点距离。
- 方向和尺度相似度。
- 在该家牌河中的空间顺序。
- 前后帧出现时间。

未匹配的新牌块表示新弃牌。它只与同一玩家最近完成、仍在有效关联窗口内的弃牌事件结合。

已有牌块消失，同时另一家的副露增加，表示该牌被鸣走。系统删除该张遮罩，但不把后续记录强行整体前移。

立直横牌或牌桌重排导致四边形变化时，追踪器更新当前四边形，遮罩随真实牌块移动。遮罩不依赖四家具有相同牌尺寸和方向。

## 9. 生命周期

系统同时维护对局会话和单局两层状态。

```text
无牌桌
  ↓ 四家牌桌结构连续稳定出现
对局会话已连接
  ↓ 手牌与空牌河基线稳定
本局识别中
  ↓ 和牌、流局、牌桌被结算覆盖或结构大幅改变
本局结束并清除遮罩
  ↓
下一局重新建立基线 / 整场结算后结束会话
```

具体规则：

- 四家核心区域连续若干帧稳定出现后，才认为牌桌可用。
- 新一局发牌完成且空牌河基线稳定后，才开始提交事件。
- 和牌、流局或结算导致牌桌结构明显改变时，立即冻结事件提交并清除本局遮罩。
- 客户端最小化、关闭、窗口捕获停止或牌桌持续消失时，隐藏遮罩并暂停识别。
- 短暂特效、窗口失焦和少量丢帧不得单独触发开始或结束。

## 10. 遮罩表现

采用用户确认的方案 A：

- 摸切：覆盖与牌块四边形一致的半透明深灰色。
- 手切：沿牌块四边形绘制金色外框，并添加轻微外发光。
- 未知：不绘制任何遮罩。

遮罩随每帧追踪到的牌块四边形更新，以适应四家方向差异和立直横牌。遮罩窗口置顶、透明、鼠标点击穿透，不改变游戏输入。

## 11. 运行控制与诊断

托盘菜单提供：

- 暂停识别。
- 恢复识别。
- 清除本局记录并重新同步。
- 显示或隐藏诊断区域。
- 退出程序。

诊断模式可以显示四家区域、多边形槽位、占用结果、当前事务和置信度。诊断关键帧只在用户主动启用时保存到本机；无需遮挡牌桌上的昵称或头像。

程序不提供任何向雀魂窗口发送输入的能力。

## 12. 失败处理

- 显示条件不符合首版要求：暂停识别并显示明确原因。
- 单项观测不稳定：等待稳定，不立即提交。
- 事件信号矛盾：记为未知，不着色。
- 新弃牌无法与可靠事件关联：保留原画面。
- 遮罩失去对应牌块：删除该遮罩，不吸附到相邻牌。
- 连续异常超过阈值：清空本局遮罩，重新建立基线。
- 捕获窗口消失或最小化：立即隐藏全部遮罩。
- 重新同步失败：保持暂停，等待牌桌进入下一局稳定状态。

## 13. 测试与验收

### 13.1 自动化测试

- `SeatProfile` 几何映射与坐标变换测试。
- 四家槽位占用检测的黄金截图测试。
- 事务聚合器的时间窗口、稳定判定和超时测试。
- 事件分类器的数据序列测试。
- 牌河新牌、移动、横置和消失追踪测试。
- 生命周期开始、单局结束、下一局和整场结束测试。
- 遮罩坐标与目标窗口位置变化测试。

事件序列至少覆盖：

- 普通摸牌后摸切。
- 普通摸牌后手切。
- 吃后弃牌。
- 碰后弃牌。
- 大明杠、暗杠和加杠。
- 岭上摸牌后手切与摸切。
- 弃牌被鸣走。
- 立直横牌。
- 和牌、流局和局间重置。
- 特效干扰、短暂丢帧和识别冲突。

### 13.2 离线回放

建立录制画面回放工具，使实时识别管线能够读取完整对局视频或帧序列。回放结果核对：

- 每家弃牌出现顺序。
- 每张牌的摸切、手切或未知分类。
- 被鸣走的牌是否正确移除。
- 遮罩四边形是否持续对应实际牌块。
- 本局开始与结束是否正确清理状态。

### 13.3 首版验收标准

- 在支持的固定显示条件下，程序能够自动进入和退出牌桌识别状态。
- 四家的检测配置互相独立，且遮罩匹配各自牌块方向和尺度。
- 已可靠识别的摸切和手切牌整局持续显示正确样式。
- 吃碰杠和局间变化不会被错误解释为普通手切。
- 被鸣走的牌不再显示遮罩，其他牌的遮罩不错误位移。
- 低置信度事件保持未着色。
- 程序不访问网络、不读取客户端内存、不注入进程、不发送游戏输入。

## 14. 后续扩展

首版稳定后，后续工作可按独立规格逐项评估：

- 更多分辨率、缩放比例和窗口尺寸。
- 更多牌背、桌布和视觉主题。
- 三人麻将布局。
- 用户辅助标定或自动几何标定。
- 更完整的离线识别质量报告。

这些扩展不进入当前实现计划。
