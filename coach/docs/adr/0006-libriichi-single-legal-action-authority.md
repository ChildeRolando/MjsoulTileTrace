# ADR-0006：libriichi 是唯一合法动作来源，退出本地第二套动作枚举

日期：2026-09-28
状态：已采纳；用户已批准方向；代码迁移中，最终验收未完成

## Context

基线为 PR #28 的 `67e1dd9c151c3fa1d9b66f14352c9c8721f60286`。
7 月统一比较规格和 8 月 helper 接入规格均将完整合法动作枚举列为非目标。
M6-A4 为核验远端报告是否漏行，引入本地独立开窗、候选枚举及单候选证明；
9 月本地 Mortal 规格继承并冻结了“两套合法动作集合必须一致”的生产前置条件。

R10–R14 表明本地枚举、资格预判、单候选证明和下游重新判断有多处重复职责。
部分固定 Mortal 已支持的合法动作被本地规则阻断。该设计提供独立检错，但没有
为 Mortal 不支持的动作创造模型分数，却让第二套规则实现拥有生产否决权。
本 ADR 接受退出这项独立检错能力的取舍，不把“来源相同的一致性检查”称为独立验证。

固定 mahjong-helper `514bb97c5a6d157fa2ed1ac804a53cb9b559d7d0` 的公开
`util` 能计算向听、进张、评分及吃碰后的何切分析；没有可直接接入的完整回合合法动作接口。
固定 Mortal 所用 libriichi 则提供确定性的 PlayerState、ActionCandidate 和动作 mask。
后者是规则代码，与神经网络给出的 Q 值职责不同。

## Decision

1. 在已批准的规则与输入范围内，**libriichi 是唯一合法动作来源**。自行推导的
   self/response 候选、和牌资格、立直/杠资格、单候选反证不再作为生产权威，
   也不保留为必须一致的第二来源、长期影子实现、兜底或验收裁判。
2. canonical 原始牌谱、事件顺序和玩家可见状态仍由现有来源映射与回放产生。
   输入完整性、支持的规则配置、身份与物理牌对应由应用核验；它们只决定输入是否
   可处理及数据是否对应，不能据此另算一份合法动作集。
3. libriichi 的规则运算独立于 checkpoint 和神经网络推理。规则结果绑定 canonical
   内容、事件前缀、玩家、窗口、规则配置、引擎与转换版本，并包含完整动作及规范化身份。
   同一结果生成模型请求、单候选证明及整局覆盖预期；实际行动在集合生成之后核对。
4. 模型只给已绑定动作评分；helper 继续提供向听、进张、打点、结构和教学事实。
   删除模型评分不改变规则结果与事实账本。helper 不得增删合法动作或否决候选全集。
5. local 与 remote-report 路径共用该合法动作来源。remote report 仍是评分来源，
   不用于还原牌局或决定应开哪些窗口；其完整性与固定规则结果比较。
   获得新分析的 remote 路径因此需要本地规则组件，但不需要本地 checkpoint。
   已存包的只读展示不因本 ADR 强制重算。
6. 采用现有七包边界：contracts 拥有规则结果契约；mortal-runtime 承载受管
   native 规则执行和模型执行这两种显式能力；desktop main 接线；reasoning 只消费
   contracts 数据/注入的窄端口，不导入特权包。规则操作不得要求加载模型权重。
7. 缺失必要输入、规则不兼容、引擎失败或转换不唯一必须明确失败；不能把失败改成
   空集合或单候选，不能默认补完整历史，不能换回本地枚举。已有支持范围不得缩小。
8. 旧合法动作实现按迁移清单退出可执行图并封存到 Git 历史，以固定提交、路径、
   符号和 blob 身份记录。不得在 src、构建、打包、默认测试或运行时保留可回退副本。
   原反例保留为新的行为回归，预期来源须可解释，不能由旧枚举器动态生成答案。

## Alternatives considered

- 只合并自建枚举与证明：减少分叉但继续承担完整规则维护，拒绝作为最终设计。
- helper 与 Mortal 双全集比较：当前 helper 无完整接口，仍需造第二套规则，拒绝。
- 直接接受模型报告或推荐动作：无法证明覆盖与身份，混淆规则和偏好，拒绝。
- 长期运行两套规则并择优/取交集：隐藏冲突、保留维护成本，拒绝。

## Consequences

减少自有规则代码与分叉路径；失去独立动作实现发现 libriichi 规则错误的能力。
固定规则案例、真实牌谱、历史反例和 helper 的独立事实测试仍保留；同一 libriichi
产生 mask 再由 Mortal 消费只算编码/传输一致性检查。
引擎规则兼容、动作粒度与输入历史语义必须在迁移中验证；有缺口须解决依赖接入或
上游规则支持，不得缩小原场景范围或恢复第二来源。上游升级需版本与来源回执。

规范和实施计划分别见
[唯一来源规格](../specs/2026-09-28-libriichi-legal-action-authority-design.md) 与
[迁移计划](../plans/2026-09-28-libriichi-legal-action-authority-migration.md)。
本 ADR 是目标设计已采纳的证据，不是代码迁移完成或 PR 验收通过的证据。

## Supersedes

- 2026-09-24 local Mortal 规格 §3–6 中“runtime 只能产模型证据”及“不得作为
  本地合法性 authority”的范围限制；身份、模型分数隔离和数据守恒继续成立。
- M6-A4 的独立本地规则枚举、双来源规则检错及单候选自产反证要求。
- ADR-0002 保留独立原始牌谱来源，取消其被扩展解释成“必须有第二套规则引擎”的要求。
- ADR-0005 的依赖边保持；mortal-runtime 的能力范围扩展为版本化规则结果与模型结果。
- INV-004 的双射改为唯一规则结果与评分/规范化动作的守恒，不再是两套规则独立一致。
