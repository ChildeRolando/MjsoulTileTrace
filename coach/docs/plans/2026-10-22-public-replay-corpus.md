# 公开牌谱采集重构

用户批准：四人日麻；完整数据集优先，增量源其次；首次采集上限 10 GB。

## 边界与实现

现有 `scripts/m6a3-scratch-tenhou-collect.mjs` 是单次试验脚本：逐盘等待、
原始字节哈希、全量内存待下载队列，且索引先完成而任务未持久化，重启会漏下载。
新工具统一放在 `scripts/replay-corpus/`，入口 `bin/replay-corpus.mjs`。
本地语料 SQLite 与用户 ReviewSession 数据库隔离，不启动 Mortal/LLM。
网络、压缩包与来源格式只在采集入口处理，下游导出既有 CanonicalEventStream。
XML 继续调用 tenhou-source 的公开 mapper，新增 MJAI 导入不改旧 mapper 或合法动作规则。

数据源分为整包/分片、静态索引、增量源三个优先级。公开可下载不等于可再发布：
来源目录记录上游链接及限制，原始数据、索引和账号信息不提交到代码仓库。
天凤官方单会话、FileIndex 至少 20 分钟、未变化索引跳过。
无法公开枚举或需账号的源明确标注，不伪装成完整支持。

同盘 ID 使用版本化、固定字段顺序的牌局内容投影与 SHA-256；排除来源 ID、
昵称、日期、段位、JSON 排版及无序手牌/副露的排列。宝牌发布时间不同的转换版本
可以属于同盘，但分别保留原始内容哈希及转换产物，不把一个版本的事件时序覆盖另一个。
缺少完整暗手的记录不与完整记录猜测合并。LSH 的相似性不作为删除样本依据。
日期、精度、时区、段位及其原始编码按来源保存；未知值不补猜。

## 不变量与检查

- INV-003/009（强制）：来源到 canonical 边界；既有公开包导出、架构检查及导出测试。
- INV-006（强制）：不支持/损坏内容保留失败位置，不能成为可分析的完整 canonical。
- INV-007（强制）：ID 算法版本、原始哈希、来源、分片版本和转换版本可追溯。
- INV-005/012：采集独立 CLI，不接触 renderer、登录凭据或用户复盘库。

真实分片发现 MJAI 缺失流局原因/听牌席位：canonical 契约增加明确 unknown/null，
同时强制这类记录不能声明 settlement complete；既有完整来源不改变。
因此采集工具、该契约、对应测试、依赖清单及本说明需要变化。新增模块是原 scratch collector
的替换，不新增跨产品抽象、治理服务或另一套规则引擎。

## 验证计划

固定真实 fixture 比较原始哈希、归一化 ID、解析、压缩、入库耗时及热重复导入；
测量多次中位数而不把网络变快归因于哈希。覆盖跨包装/格式去重、红牌及行动差异、
元数据合并、分片中断恢复、限额、失败重试、损坏归档、并发和批次提交。
批量源验证后才处理流式源，所有下载受总字节预算控制。
最终测试和实测结果补录在本页，未运行的验收不声明通过。

## 实测结果（2026-10-22）

运行环境为当前 Windows 工作站、Node 24.15.0、本地磁盘。用户批准的是 **最多**
10 GB，本轮先完成三个完整分片，不为用满额度下载额外数据。

| 完整分片 | 下载字节 | 可入库独立牌谱 |
|---|---:|---:|
| 雀魂 `majsoul-throne-2019.tar` | 54,620,160 | 7,602 |
| 天凤 `tenhou-houou-2009.tar` | 49,879,040 | 6,897 |
| 天凤 `tenhou-release-00005.parquet` | 69,035,235 | 21,724 |
| 合计 | **173,534,435** | **36,223** |

另有 1 条不完整牌谱登记为失败。36,223 个原始表示、37,223 条来源记录；额外 1,000 条
来源记录来自先前本地小样本验证与正式分片导入的重叠，没有产生重复 games。
三个正式分片完成；初始本地小样本的独立验证任务仍保留 paused，不伪造完成状态。
数据库与下载缓存合计约 446 MB，原始数据全部在仓库外。

hhim8826 `f9a5a0dca2ce4a09d73749582694803c96b04b04`。完整下载核对 LFS SHA-256。

`last-run.json`、原始分片和 `evidence/` 测量回执。

### 同条件性能比较

`scale-benchmark.mjs` 每次使用空数据库、相同真实 Parquet 的前 5,000 盘，
每组重复 3 次，计时包括最终提交、checkpoint 和关闭。不包含网络下载。

| 最终版本的写库策略 | 三次总耗时（秒） | 中位数 |
|---|---|---:|
| SQLite 默认约 4 MB 自动 checkpoint | 12.301 / 11.872 / 12.456 | 12.301 秒 |
| 64 MB 有界 WAL，批量 checkpoint | 5.833 / 6.251 / 6.423 | **6.251 秒** |

中位耗时减少 **49.2%**，约 **800 盘/秒**；改善超过本组波动。
新路径指纹编码、内容 SHA-256 和原始 SHA-256 合计约 **0.13 ms/盘**，无需 LSH。
归一化仍是主要 CPU 成本。更早未加来源反查索引的同类实验为 15.218 → 5.755 秒；
最终结论使用上表，保留两次证据，不挑最快一轮。

Parquet 同一 4,000 行组解码的三个配对试验：JS Zstd 为 541.0 / 511.8 / 477.8 ms，
Node 原生 Zstd 为 305.6 / 242.3 / 249.3 ms；输出摘要相同，中位解码耗时下降 51.3%。
该实验在完整采集期间进行，属于组件证据，不据此推算端到端下载加速。
逐行小切片会反复解码同一 Parquet 行组，已改为每行组只解码一次。

来源反查初次审计暴露 `SCAN observations`；增加 hash 索引后执行计划为
`SEARCH observations USING INDEX observations_hash (hash=?)`。上述最终基准包含该索引的写入成本。
默认内存缓存 64 MiB，WAL 按阈值回收；不把全库 ID 常驻内存。

旧 scratch 路径仅原始字节哈希和文件写入，本地少量样本可能比新路径更快；新路径增加
语义去重、压缩和来源索引，不能把不同工作量的本地耗时宣称为同条件加速。
主要采集收益来自直接获取完整分片，避免数万次逐盘远程请求与等待。天凤官方的
单会话/间隔限制仍遵守，没有通过增加远程并发获得这些数据。

### 数据正确性与边界

- 全量 36,223 盘复算 ID，**零不一致**。
- 11 个仓库真实 XML fixture 与既有 mapper 的四视角结果组合出的 MJAI 逐盘 ID 一致。
  另取一盘官方 XML 与公开数据集 MJAI 做独立跨源验证，ID 一致。
- 三个来源各按 hash 顺序抽样 100 盘，四视角共 1,200 次 canonical 转换/既有重放校验：
  **1,188 次通过**；3 盘的 12 个视角拒绝，其中 8 个 `dora_kan_mismatch`，
  3 个 `physical_tile_overflow`，1 个 `self_tile_not_owned`。
  原始内容保留，不通过移动事件或放宽重放校验把这些结果计为成功。
- 历史超北四局可以保留原始 MJAI/XML 和同盘 ID，但现有 canonical 不支持北风局；
  导出明确拒绝。规则或流局事实缺失仍是 partial；未运行 Mortal 或完整教学分析验收。
- 所有平台均已支持的声明不成立：本轮实现的是已核实的天凤/雀魂整库、天凤公开增量和
  通用公开归档入口。一番街、天月等尚无本轮可核实的公开枚举入口，具体范围见工具说明。

## 变更控制报告

- **Scope / Locality**：替换 scratch collector，新增独立 CLI 的来源目录、流式归档读取、
  同盘指纹、SQLite、下载恢复和导出模块；依赖仅属于开发采集工具。没有修改桌面产品流程。
  `contracts/event-stream` 必须表达缺失流局事实；`round-state` 同步允许 unknown，
  `reasoning/replay-audit` 将 unknown 映射为其既有 null。其余 mapper 和规则引擎不变。
- **Invariants**：INV-003/009 由包公开导出、架构检查、四视角导出测试执行；INV-006 由
  schema 的 partial 约束、损坏输入测试、导出重放校验执行；INV-007 由版本、原始哈希、
  重启去重和多来源测试执行。INV-005/012 不新增 UI/IPC 或修改用户档案边界。
  没有删除或放宽已有守恒校验。数据集中未知事实是显式扩展，不冒充 complete。
- **Traceability**：整包固定上游版本与已知校验值，观察记录保留来源定位、原始表示、日期精度
  与段位体系；mapper 和内容身份均版本化。ID 不替代来源事实或历史分析内容哈希。
- **Replaceability**：来源只生成普通 job，归档只生成 record；新增镜像可用 manifest 接入，
  下游仍消费既有 canonical。SQLite 拥有采集状态，不进入 ReviewSession 持久化。
- **Recoverability**：单写者锁、已提交成员游标、持久队列、Range/版本校验、累计预算和失败
  定位可重复验证。坏记录与存储/下载限额分别处理；不会把限额中断的成员跳过。
- **Semantic Load**：没有新增架构层抽象；原 scratch collector 的职责折入现有 scripts 层。
  SQLite 表和来源 adapters 为这项采集功能的内部实现，不新增全局治理机制。
- **Verification**：build、typecheck、architecture 和 package import smoke 均已通过；
  首次全量测试期间同时进行重采集，出现两个既有超时及新测试文件 runner 不兼容。
  保留失败日志，修复 runner 后停止竞争负载，全量复跑 237 文件 / 2,886 测试通过，
  既有 5 文件 / 22 测试跳过；没有增加超时或删断言。随后新增 wrapper 元数据、ZIP 与
  429 三项回归，专项 24 项全部通过。最终完整回归为 **237 文件 / 2,889 测试通过**，
  既有 5 文件 / 22 测试跳过，75.30 秒；最终架构检查 8 包 / 574 文件 / 2,886 imports，
  零违规。真实已入库样本经 CLI 导出 canonical 和元数据 sidecar 成功。下载写入使用
  writeFile 保证完整写出每个 chunk，专项 24 项再次通过。
  没有运行远端 CI、原生学习实验或桌面产品发布验收。
