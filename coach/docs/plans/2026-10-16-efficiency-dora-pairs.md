# 牌效率与保宝配对回归及合法扫描

## Scope

落实已批准的配对实验：严格有序主张、全部 E×D、连续 Q 差、三组特征消融与分组 SVR，
从训练反例的原始见证扫描库存／指示牌／点数／时间，再做合法补样和不回流训练的威胁扩展。
配置和全流程由 question-lab 承载，不增加桌面入口，不修改生产 ReviewSession 或复盘评分语义。
完整操作定义与预算见 [README](../../packages/question-lab/README.md)。

## Locality

- contracts：新增 v2 研究、配对、标签、SVR、扫描和结果 schema；v1 不变。
- question-lab：复用 canonical、事实、完整合法动作及 managed runtime 的公共 API；
  原有 label 逻辑提取为共享函数，只增加 v2 编排。独立 Python 环境沿用既有锁定依赖。
- 不新增包间依赖，不深导入其他包，生产与 renderer 不获取研究入口。
- 架构检查：8 包、560 源文件、2780 import，0 违规；架构检查器 129 项和 emitted package smoke 2 项通过。

## Invariants

新增保护点已登记 INVARIANTS；没有删除不变量，也没有第二套麻将规则实现。

## Traceability

规则来自固定 libriichi，事实来自现有 helper，估值显式为启发式，Q 来自固定 Mortal。
研究主张是解释假设。所有 E×D、分数、来源组、权重与模型归档；版本号、完整请求／生产者哈希、
见证哈希、扫描坐标及实际变化可追溯。旧档案只读重新验证和重标，不沿用旧标签。
成功构造逐条落盘；原生拒绝、固定条件破坏和不可达目标分别记录，预算耗尽不宣称无解。

## Replaceability

原生构造、规则与 Mortal 评分继续由 mortal-runtime 管理；学习是独立进程的版本化数据接口。
换学习实现只需保持 v2 契约，不能绕过合法局面和可见特征；换模型需新档案身份。
报告复用现有 Coach/Arena 37 张 SVG，不引入网络图片、LLM 解释或额外服务。

## Recoverability

最先失败的检查：纯特征／schema 测试（集合准入、未知事实、差值、第三选择），
Python 已知线性／非线性与独立集污染测试；原生 fixture 再覆盖真实 58ba 反例及四条扫描轴、四类威胁。
生成和扫描分别有连续／中断恢复对照，比较科学记录、模型快照和实际新增推理；篡改计划拒绝恢复。
原生 fixture 是合成牌山，不含用户牌谱；仅运行真实 native 测试需要本地固定资产。

## Semantic Load

不新增架构包。v2 PairObservation 防止“全局极值相同但竞争行动不同”的信息丢失，隔离配对表达变化，
旧 v1 分类 sample 不能作为连续配对契约的 owner。PairStudy 在既有 LabBatch 旁编排固定研究：
严格准入、最终研究冻结和物理见证扫描与 v1 开放配置／分类不同，不能悄悄改写 v1。
其规则／评分／事实仍走共享 runtime，未复制或放宽生产逻辑。
