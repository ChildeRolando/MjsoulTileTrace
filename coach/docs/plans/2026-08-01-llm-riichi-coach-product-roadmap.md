# LLM 日麻教练完整开发路线图

> **历史路线图：** 本文件保留最初的完整产品拆解与决策背景，其中状态、测试数量和部分缺口已过时。当前开发顺序与完成状态请以 [`docs/development/ROADMAP.md`](../../docs/development/ROADMAP.md) 为准。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付一个本机运行的类 Agent 应用：用户完成一次 LLM 设置并通过产品内的雀魂国区官方页面登录后，从近期可分析牌谱中选择四人南风对局，选择 Mortal 4.1b 或 Akagi Native，得到可回放、可审计、可追问并可恢复的整盘教练会话。

**Architecture:** 产品由五条边界清晰的管线组成：本机持有的雀魂账号同步与局面重放、麻将模型适配、确定性五轴证据、受约束 LLM 教练、会话工作台。Mortal/Akagi 只提供候选动作和选择分；教练结论来自可审计计算和教学证据，LLM 只负责表达，不能创造事实或模型内部原因。

**Tech Stack:** Electron、TypeScript、Zod、Vitest、Node.js、本机 React 工作台、本地加密保险库、跨平台系统安全存储、SQLite、SSE、受管 Akagi Native、Mortal 人工验证接力、OpenAI 兼容接口。

## 1. 一句话现状

项目已经完成了“防止教练胡编原因”的严格地基、统一动作/候选/评分/事实账本，以及 M2-A 的三手型牌形、等待与振听事实层；但还没有可供普通用户粘贴牌谱 URL 使用的桌面产品。

更准确地说：

- 推理与契约层：已有真实代码、测试和固定牌谱回归；
- 真实输入与模型层：只有适配边界和夹具，尚未接通生产牌谱与生产引擎；
- Agent 产品层：服务端、数据库、LLM 调用、会话和三栏 UI 尚未建立；
- 因此当前不能完成“粘贴 URL → 自动生成整盘教练会话”。

### 3.1 ✅ 牌效率课程与训练工具（独立成品）

已验证：

- 18 节课程、54 道即时反馈题；
- 240 个训练变体；

### 3.2 ✅ 严格证据型推理原型

`coach/packages/contracts` 与 `coach/packages/reasoning` 已完成第一代严格推理核心：

- Mortal 报告事实归一化，`modelReason` 永远为 `unknown`；
- 在导入边界删除对手暗摸牌信息；
- 按决策时点重放玩家可见场景；
- 普通形向听与未加权有效牌；
- 对每名立直者分别计算现物和一发窗口；
- 五轴覆盖目录与同构候选账本；
- 同时保存支持模型动作和支持实战动作的因素；
- 证据注册、可信重算、结构验证；
- 确定性中文解释；
- 东一局 6 巡和 7 巡真实牌谱回归。

当前回归保证：

- 6 巡：牌效支持切 2 筒，防守支持摸切对立直者现物 6 索；
- 7 巡：牌效支持切 7 筒，防守支持切现物 8 筒；
- 不得生成“6 索是牌效冗余张”或“切 8 筒保留更好牌形”；
- 不声称知道 Mortal 的选择原因。

### 3.3 ✅ 统一比较架构 Slice 3：结构化 FactorPipeline

已完成：

- source-neutral `MahjongFactEnginePort` 与严格 JSONL 协议；
- 应用内置、固定版本并校验 SHA-256 的 Windows Go sidecar，普通用户无需 Go 或可执行文件路径；
- 直接复用固定提交的 `EndlessCheng/mahjong-helper`：向听、有效牌、改善、役种、完成手点数、筋/壁/one-chance/早外等进入结构化事实；
- 每个 canonical candidate 独立投影为五轴同构账本；
- 确定事实、带假设确定事实和版本化启发式严格分级；启发式永远不能产生 `DeterministicPreference`；
- 数字、集合、分类差异均保留，跨轴冲突不擅自加权；
- 事实引擎错误只允许使用项目自有诊断码，不让 sidecar 任意文本进入 LLM 边界；
- 威胁、局面、动作和证据均由哈希/事件身份绑定，矛盾场景 fail closed；
- 东一局 6/7 巡通过真实打包 sidecar golden，而非测试内自证。

最终验证：Go 测试与 `go vet` 通过；40 个 TypeScript 测试文件、281/281 测试通过；类型检查、编译后包导入、根目录 19/19 和依赖审计通过。完整代码复审为 Critical 0；12 项 Important 和 2 项 Minor 均已修复。

## 5. 主产品开发顺序

以下顺序是当前推荐的关键路径。每个里程碑都必须先提取独立规格，再写逐文件 TDD 实施计划；不把整个产品作为一次不可审查的大改动。

### M0 ✅ 严格推理与统一候选地基

**状态：完成。**

交付物就是第 3.2–3.5 节所列能力。它解决了最重要的可信度问题：模型分数、教练判断、证据和未知事项已经从数据结构上分离。

### M1 ✅ Slice 3：统一 FactorPipeline

**目标：** 让 `StructuredComparisonSet` 经由统一的麻将事实引擎端口生成同构账本，所有因子都以 canonical `actionRef` 为键，有模型与无模型比较共用同一管线。Slice 3 复用成熟麻将算法，不重新开发完整牌效引擎，也不采用外部引擎的最终推荐。

工作包：

1. 建立 source-neutral `MahjongFactEnginePort`、结构化候选账本和差异契约；
2. 集成应用托管、版本固定的 Go JSONL sidecar，直接调用 `EndlessCheng/mahjong-helper/util` 的结构化 API；
3. 接收向听、有效/改善牌、完成手牌点数等确定值，并以版本化上游估算接入役种集合、默听/立直平均打点、局收支和速度指标；
4. 把现有现物、一发和威胁事实迁移为本地重放账本，同时接入 helper 的筋、壁、NC/OC、早外和逐威胁风险刻度；
5. 为每项输出标记 deterministic / upstream estimate；估算可比较和展示，但不能进入 `DeterministicPreference`；
6. 实现确定性支配：同一轴中可严格证明一个动作不劣且至少一项更优；
7. 实现跨轴冲突保留，不在缺少教学规则时擅自选边；
8. 保持模型评分可插拔：删除评分不能改变事实、候选结果和教练偏好；
9. 保留 legacy bridge，直到新旧东一局回归完全等价；
10. 对其余非弃牌动作生成明确的未支持状态，不把它们伪装成弃牌牌效。

**完成判据：** 同一个两动作问题，无论候选来自 Mortal、Akagi、实战或用户草稿，都产生相同的确定性五轴结果；模型评分只影响模型偏好、分差和详略级别；外部事实引擎固定版本、许可证完整，终端用户无需配置可执行文件或 Go 运行时。

**状态：完成。** 固定 sidecar、五轴账本、证据级别、差异、确定性 dominance、真实 East 1 回归和安装资源完整性均已通过自动验收。

### M2 🟡 五轴分析能力补全

**目标：** 把“知道应该分析哪些因素”推进为“能够可靠计算足够多的因素”。

按依赖拆为四个子项目：

#### M2-A ✅ 局面事实与牌形

- ✅ canonical 事件流已完成副露、立直宣言/接受、手切/摸切、被鸣弃牌、宝牌、点数和公开牌；
- ✅ 公开/我方私有状态、事件前缀归约、决策快照和 V2 五轴投影已完成；
- ✅ 普通形、七对子、国士分别计算向听、有效牌和剩余枚数；
- ✅ 非劣结构覆盖面子、雀头、搭子、浮牌与复合等待，并以稳定引用进入事实账本；
- ✅ 舍牌、同巡、立直三类振听和 response-opportunity 完整度已实现，缺历史时 fail closed；
- ✅ 弃牌候选会生成动作后的 13 张手牌，鸣牌/荣和响应使用独立决策窗口；
- 🟡 生产牌谱来源完整度仍依赖 M5；完整合法动作枚举与鸣牌后分支搜索仍待实现。

#### M2-B 打点与和牌质量

- 在 Slice 3 上游役种/点数基线之上补足公共 API 未暴露的精确符番、逐等待役种和规则变体；
- 已确定役、潜在役和无役风险；
- 宝牌、赤牌、门清、立直/默听与副露价值；
- 符番和亲子打点区间；
- 等待种类、枚数、振听和可荣和性。

#### M2-C 🟡 防守、威胁与牌河阅读

- ✅ V1 逐威胁防守矩阵已完成：`defense-matrix/v1` 为每个弃牌候选生成一行一威胁的单元格，确定性现物安全绑定具体河事件，结构单元格（筋、壁、no/one-chance、早外、字牌枚数、版本化 helper 风险刻度）request-bound 且仅启发式；
- ✅ 分对象现物不跨威胁泛化、不合成总数、helper 风险刻度绝不伪装成 Mortal/Akagi 铳率；
- ✅ 东一局 6/7 巡 6s/8p 现物防守、2p/7p 牌效、applied 偏好为 null 的真实回归锁定；
- ⬜ 多家立直/副露威胁中的行为与等待启发式、牌河牌型推断（染手、对对、役牌、宝牌周边、手切序列）仍待实现；
- 结构、行为和等待三级启发式分别标注来源与限制；
- 启发式危险度不得称为 Mortal 铳率或精确放铳概率；
- 校准风险只有在明确数据集、规则与验证后才进入 `calibrated_statistic`。

#### M2-D 顺位、局收支与选择权

- 点差、亲家、剩余局数、本场和立直棒；
- 和牌、放铳、被摸、流局听牌/未听的直接结果路径；
- 必须和牌、只需听牌、保连庄或回避末位等目标；
- 安全牌库存、回旋余地、鸣牌/立直/杠的不可逆性；
- 未来攻守切换和危险牌后置。

**完成判据：** 每个分析维度都有 implemented / heuristic / unsupported / blocked_by_missing_data 状态；缺失维度只能进入未知列表，不能被 LLM 补写。

### M3 ⬜ 教学规则与可审计资料

**目标：** 支持“没有模型时比较用户指定的两个动作”，并让经验结论可以追溯到麻将书籍或登记资料。

工作包：

1. 定义 `TeachingEvidence`、适用条件、版本、定位和内容哈希；
2. 建立本地冻结证据仓库及 MCP 资料适配边界；
3. 资料不可用或哈希变化时 fail closed，不沿用未验证内容；
4. 处理两个来源的包含关系、冲突和无法排序；
5. 将教学规则写成只读取因素的版本化规则，不能读取模型首选或特定牌谱 ID；
6. 在 M2 所需输入完备后激活 PF-03，而不是仅靠“一发+两向听”硬套；
7. 建立更多通用攻守、打点、顺位和选择权规则及反例夹具。

**完成判据：** 无模型的限定两动作问题可以输出确定性结论、带来源经验结论或“无法可靠取舍”；不会为了补齐五轴而追问无关条件，也不会伪造书名、页码或统计口径。

### M4 ⬜ 理由选择、LLM 教练与输出验证

**目标：** 将可信结构化结论变成自然、具体、可追问的教练回复，同时保证 LLM 无法越权。

工作包：

1. `FrameResolver`：区分实盘综合题、平面何切、局面修改、独立假设和概念题；
2. `PreferenceResolver`：分别产生模型偏好与教练偏好；
3. `ReasonSelector`：选择模型同向可观察因素和教练决定性理由；
4. 高分差详解、低分差具体一句话、无模型回答的三个输出模板；
5. OpenAI 兼容客户端、流式响应、超时、取消和受控重试；
6. `ExplanationValidator` 从可信输入重算引用、数字、偏好、因素和资料；
7. 拒绝空泛话术、单边藏证据、虚构事实和模型因果归因；
8. 两次 LLM 失败后退回确定性模板。

**完成判据：** 对东一局 6/7 巡自动生成正确的攻守解释；删除模型评分后，同一管线仍能回答用户指定的动作比较；任何可见麻将断言都能回指结构化证据。

### M5 🟡 雀魂国区账号同步与完整重放

**目标：** 通过产品内的雀魂国区官方登录取得本机会话，自动同步近期可分析牌谱，并把选中的完整记录可靠地变成按主视角冻结的决策流。

**当前状态：M5-A 已完成，M5-B 工程实现与自动化验收已完成，真人登录冒烟待执行。**
M5-A 已交付 renderer-safe DTO、特权源包、秘密值脱敏、国区协议/端点资源固定与
哈希校验、Liqi 帧编解码、登录结果六字段投影，以及 official schema / vendored
proto / RPC map 三方兼容门禁。M5-B 已交付隔离 Electron 官方登录窗口、相关帧
捕获、操作系统安全后端包裹的本机加密令牌保险库、跨重启保守恢复、注销清理和
安全 IPC/renderer。所有自动化测试只使用假凭据；真人登录冒烟因本机尚未取得
Electron 43.3.0 官方可执行文件而未运行。M5-C 可按总规格继续使用 fixture
transport 开发最近 30 场目录同步与“仅显示可分析条目”；总规格 H1 保留给
M5-E 登录→目录→下载→重放全链路人工验收。M5 整体仍未完成。

工作包：

1. 用隔离 Electron 窗口打开国区官方登录页，不接触密码和验证码；
2. 在本机加密保存会话令牌，跨重启验证恢复，不交给第三方；
3. 同步最近 30 场元数据，只把四人南风、标准规则和受支持协议条目交给界面；
4. 解析/生成无凭据分享 URL，并根据登录账号唯一确定主视角；
5. 选择牌谱后按需取得完整记录，验证身份、来源、大小和内容哈希；
6. 用固定 protobuf descriptor 解码并转换为版本化 canonical 事件流；
7. 重放四家牌河、副露、立直、点数、宝牌、剩余牌数和结算；
8. 为每个主视角决策建立决策窗口与实战动作；
9. 登录、下载或协议变化时明确失败，不用 LLM 猜数据。

**完成判据：** 用户登录后能看到近期可分析牌谱；关闭并重开应用后会话可安全恢复；选中的真实牌谱可以离线重放到每个原子事件，并且主视角、局数、手牌、牌河、点数和实战动作与雀魂回放一致。详细边界见 `coach/docs/specs/2026-08-11-mahjong-soul-account-sync-design.md`。

### M6 ⬜ 双引擎生产接入

**目标：** 让同一牌谱会话可以冻结选择 Mortal 4.1b 或 Akagi Native，并输出相同的结构化候选契约。

#### M6-A Mortal 4.1b

- 应用打开官方 Mortal 页面并复制牌谱 URL；
- 用户本人完成 Turnstile 和提交；
- 应用等待并持久化 `awaiting_mortal_verification`；
- 用户粘贴结果 URL 后，校验 HTTPS、受信任主机、重定向、大小和内容类型；
- 匿名下载结果并核对牌谱、主视角和网络标识；
- 解析全部主视角候选概率及原始字段；
- 页面变化时保留会话并报告适配错误，不自动猜测。

#### M6-B Akagi Native

- 固定可验证的运行时、权重、版本清单和校验和；
- 首次启动由应用准备和自检，不要求用户填写路径；
- 将完整牌谱送入本地推理并限制资源并发；
- 在获得真实、版本固定的输出 schema 后实现 typed adapter；
- 对合法候选 logits 使用稳定 softmax，并保留原始 logits；
- 运行时准备失败不影响用户改选 Mortal。

**完成判据：** 两种引擎都能对同一真实牌谱生成完整 `StructuredComparisonSet + ModelEvaluation`；界面只标明引擎和版本，不制造“正式/非正式”等级差异。

**外部约束：** Mortal 的人工验证不能被自动绕过。Akagi 程序与权重能否随安装包再分发，必须在发布前核对授权；若不允许再分发，需改为应用管理的合规下载流程。

### M7 ⬜ 本机 Agent 服务、持久化与安全

**目标：** 把一次分析变成可恢复、可追问、可删除的长期本机会话。

工作包：

1. 本机 API 与 SSE 事件协议；
2. SQLite 会话、牌谱、事件、决策、候选、证据、讲解和消息表；
3. `created → fetching → validating → engine → normalizing → coach → ready` 状态机；
4. 阶段级重试、应用重启恢复和中间产物复用；
5. 一牌谱一会话、自动标题、重命名和删除；
6. 每条用户消息保存发送瞬间的不可变 `scene_snapshot`；
7. 各平台系统安全存储保存 API Key；
8. 日志过滤密钥、授权头、完整请求体和 Mortal URL 查询参数；
9. 分析时冻结引擎、版本、阈值和 LLM 模型标识。

**完成判据：** LLM 失败不影响查看牌桌和模型数据；单项讲解可独立重试；重启后继续原任务；删除会话会删除其全部本地数据；前端、SQLite 和日志中都没有 API Key。

### M8 ⬜ 三栏工作台

**目标：** 实现用户已经确认的交互布局。

工作包：

1. 首次设置：Base URL、API Key、模型名和连接测试；
2. 左栏：新分析、历史会话、状态、重命名和删除；
3. 中栏：四家牌河、副露、我方手牌/摸牌、宝牌、场况、点数与顺位；
4. 候选动作在牌面或牌上方直接显示选择分和热力条；
5. 控制器：上一/下一局、错误、切牌，以及原子事件后退/前进；
6. 右栏：教练主动开场、当前错误、原始候选证据和对话；
7. 发送消息时冻结当时中央局面作为隐藏上下文；
8. 导航改变当前视图，但不改变历史消息绑定的快照；
9. 窄屏下左右栏成为抽屉，中央牌桌保持视觉中心；
10. 所有颜色信息增加文字、图标或形状区分。

**完成判据：** 用户可以从新建分析完成到整盘报告，并用所有导航按钮定位错误和逐切追问；历史会话重开后视觉状态、报告和消息一致。

### M9 ⬜ 端到端加固与跨平台发布

**目标：** 从工程演示推进为可以长期使用的首版应用。

工作包：

1. 两个引擎的固定真实牌谱端到端夹具；
2. Mortal 等待验证、关闭、恢复和安全导入测试；
3. Akagi 首次准备、校验失败、中断和升级迁移测试；
4. LLM 模拟端点、超时、无效输出和确定性降级测试；
5. SQLite 崩溃恢复、迁移、删除和隐私测试；
6. 三栏 UI 的键盘、窄屏、无障碍和大牌谱性能测试；
7. Windows、macOS、Linux 安装、升级、卸载和本地数据保留策略；
8. 日志导出与隐私审计；
9. 不支持牌谱、第三方协议变化和资源不足的明确错误体验；
10. 发布候选版真实牌谱验收。

**完成判据：** 总规格 20 条首版验收标准全部有自动或人工证据；用户无需配置 Akagi 路径，雀魂登录只发生在产品内官方页面，令牌不交给第三方，也不会遇到静默换模型或无证据麻将结论。

## 7. 需要用户参与的验收节点

工程实现期间默认继续自主推进，只在以下节点需要用户：

### H1：雀魂真实账号全链路验收

在 M5-E 执行唯一一次需要真实雀魂账号的人工验收：用户本人在 Electron 官方页面
登录，重启后确认会话恢复，核对近期列表只显示可分析的四人南风牌谱；再选择一份
熟悉牌谱，对照官方回放检查本人座位、局序、手牌、牌河、副露、宝牌、点数、响应
窗口、实际动作与结算。退出账号后，近期缓存应消失而已生成报告仍可打开。用户不
提供 token、Cookie、开发者工具截图或手工协议数据。

### H2：首份可信教练报告验收

M2–M4 贯通后，用已知牌谱检查：

- 东一局 6/7 巡是否仍是攻守解释；
- 简评是否具体；
- 详解是否保留反方因素；
- 无证据时是否诚实停下；
- 无模型假设题是否只使用题目给出的条件。

这是最重要的麻将产品验收节点。

### H3：三栏交互验收

M8 首个完整界面出来后，确认牌桌视觉中心、热力显示、导航语义、右侧对话和消息快照是否符合实际使用习惯。

### H4：发布候选版验收

在一批真实南风牌谱上连续使用，确认失败恢复、运行时间、安装体验和报告质量，再决定首版发布。

除上述节点外，框架选择、数据库表、进程通信、测试和打包等工程细节不需要用户逐项批准。

## 8. 关键风险与提前处理

| 风险 | 控制方式 |
|---|---|
| LLM 编造合理但错误的原因 | 决定性计算、双向账本、版本规则、输出重算和确定性降级 |
| Mortal Turnstile | 只做人机接力，不绕过验证；等待状态可恢复 |
| Mortal 页面或 JSON 变化 | 版本化解析器、固定夹具、身份核对和 fail closed |
| Akagi 私有格式变化 | typed port、版本冻结、真实 schema 夹具；不猜未知 JSON |
| Akagi 权重分发授权 | 发布前核对授权；必要时采用应用管理的合规下载 |
| 牌河启发式被写成精确铳率 | 强制 provenance、confidence、limitations 和措辞验证 |
| 五轴不完整却给出确定结论 | 覆盖清单和 policy gate；缺输入时对应轴退出判断 |
| 长牌谱提示词过大 | 整盘摘要、错误索引、分项预生成、消息局面快照 |
| API Key 泄漏 | Credential Manager、前端不可读、日志与数据库扫描 |
| 第三方协议变化 | 获取器/适配器隔离，保留中间产物并提供阶段级重试 |

## 9. 当前完成度应如何理解

不建议给整个产品一个虚假的单一百分比，因为“281 项内核测试”与“零个可用 UI 页面”无法线性相加。更诚实的判断是：

- 架构设计：主干已经确定；
- 统一推理架构：Slice 1–3 已完成，事实计算和解释边界已经贯通；
- M2-A 牌形与振听：已完成并进入统一事实账本；
- 真实数据与双引擎：边界已设计，生产接入尚未完成；
- 用户可见 Agent：尚未开始；
- 首版发布：仍需 M2–M9。

项目已经越过“概念验证是否可信”的阶段，并完成 M2-A：canonical 重放、三手型牌形、复合等待、baseline 荣和资格和三类振听都已进入可审计账本；同时完成 M2-C V1：逐威胁防守矩阵的确定性现物与结构启发式已收束为 `defense-matrix/v1`，东一局 6/7 巡回归已锁定。M5-A 的雀魂国区协议与安全契约地基、M5-B 的 Electron 会话工程实现与自动化验收也已完成；下一项是 M5-C 近期目录，之后完成记录下载和 canonical 映射，并在 M5-E 执行真实账号全链路 H1。在进入 M6-B 前仍需取得真实、版本固定的 Akagi Native 输出样本与分发授权证据。
