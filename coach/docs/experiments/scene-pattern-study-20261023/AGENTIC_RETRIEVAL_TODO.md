## 当前能力与独立实施边界

Arena 已由模型选择是否调用 search_knowledge、提出查询、根据返回继续查询或提交讲解。场景提示允许改写查询、不采纳模式提示；B 组没有模式仍可检索，D 组模式仅补充关注点。模式命中不是卡片访问门槛。

原批准试验固定分词、别名、排序及检索预算。本轮只修订知识条件并复标原 60 局，标注模型直接收到全部 40 张卡，不经过 RAG。检索改造放在独立版本中，避免同时改变知识内容和检索方式后无法归因；不接入生产复盘。

## 优先修复现有工具的一致性

contracts 的 ArenaRagTopicSchema 已包含扩展主题，但 runner 的 ARENA_RAG_TOOL_PARAMETERS 中 context.topic / filter.topics 仍只向模型暴露 tile-efficiency 与 shape-flexibility。文字 query 不加 filter 时仍能检索全部卡片。

先同步工具枚举与契约，核对工具声明返回条数与本试验每次三条上限一致。此修复会改变冻结 runner 摘要，进入独立检索版本。本次直接读取全部卡片的复标不受这个枚举缺陷影响。

## Small-to-big：短片段定位，完整卡片解释

以知识卡中的独立论点或已核对的原文段落作为小块，保存父卡 ID、原文章节及段落位置。命中后读取完整知识卡，并在有可靠定位且需要更多说明时，附上对应原文小节或邻近的条件、例外段落；按预算限制范围，不机械返回整章。当前检索本来就会返回完整知识卡，不能把这个已有行为冒充新增能力；新增价值在更精确的定位及可追溯的教材上下文补充。

同一父卡的多个片段只返回一次完整卡，不重复占用六张去重卡的配额；附加原文上下文同样计入总 token 预算。模型可以读取、继续查询或停止；模式不限制可检索的父卡。实际引用绑定读取过的父卡版本及原文来源，不能引用只看到标题而没读到的内容。

## Context enrichment：补足片段所属上下文

检索片段附加教材体系、章节标题、讨论主题、父卡 ID、版本及相应条件/例外提示，帮助识别“这是一般原理还是特定模拟结论”。优先从现有卡片和来源元数据确定性生成，不先引入额外 LLM 摘要步骤。

例如“安全牌”片段应能看出是自身舍牌依据还是立直后通过牌；“点况”片段应能区分一般半庄原则与末局特定顺位示例。增强文本必须有来源，不添加当前牌局推测、答案或人工评测标签，也不能把模式工程阈值写成教材边界。原文尚未核对的牌图例题继续排除。

两个机制互补：上下文增强帮助找到正确片段，small-to-big 让模型读取完整适用条件。优先沿用现有词项检索和工具边界，不为这一步引入向量库、图数据库或新通用框架。

## 验收与停止条件

1. 先用少量开发局面检查定位、去重和预算，再冻结知识、片段索引、模型和可见事实，用新的未见样本比较现有检索与两项组合；首轮仅判断组合是否有益，确有必要时才追加拆分比较。
2. 先保持相同检索调用次数、唯一父卡数量与总 token 预算；失败、无结果、未读取和重复命中分别保留。
3. 覆盖无模式命中仍自主检索、同词不同语境、命中概念却漏掉例外、两套来源观点不同、多个片段命中同卡、来源缺失、预算耗尽和来源内恶意指令。
4. 评价必需知识召回、无关材料、条件误用、引用支持、讲解盲评以及 tokens、耗时和失败率。若只有返回更多文字而无质量改善，停止扩展。
5. 新接口只沿用 contracts / Arena RAG / runner / study 的既有责任；独立离线验证后再考虑生产接入。本轮不追加检索实验调用。
