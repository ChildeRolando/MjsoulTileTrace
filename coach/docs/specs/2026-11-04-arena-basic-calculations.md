# Arena basic calculation module

The optional static module extends Arena's existing modular assembly and fact-engine boundary. It derives one result for every offered canonical discard in the original order from the bound decision-time facts using `projectCandidate`, `analyzeHand13`, and `validateHand13Result`. It exposes only shanten, effective tiles and unseen copies, and dora count. Unseen copies include tiles in unknown locations and are neither live-wall counts nor probabilities. Failed and unavailable calculations remain explicit. No action ranking, estimate, model output, label, or teaching material enters this module.

The existing raw and MCP paths retain their behavior. A separate opt-in configuration selects this module, with no model-callable tools. Assembly validates exact candidate order and strict output shape. It uses standard hand13 mode, since efficiency mode does not compute dora; missing indicators remain unknown. Engine identity and module version provide provenance; size and run budgets remain unchanged. Coverage, failure, raw regression, red tiles, calls, and blind-boundary checks are verified before use. This is a basic subset, not the complete Coach helper.

## Optional hand structure facts

`handStructureFacts` is independently opt-in and requires the complete legal candidate set. It may accompany `basicCalculations` but rejects the older mixed helper and callable tools. The main-owned adapter projects each bound candidate to `hand_structure/v2`, validates each engine result and exposes only family applicability/shanten and the returned non-dominated minimum-shanten decompositions. Each row carries its own action reference alongside its facts; assembly binds the case and all ordered row references to the observation, so missing, extra or reordered rows fail closed. Per-candidate projection or engine failure is retained as an unavailable or error row.

Returned decomposition references are mapped to candidate-local indices, preserving repeated group occurrences and their membership. Invariants describe the intersection over the complete non-dominated set; alternatives describe returned decompositions only. A truncation flag explicitly identifies omitted decompositions. Tile34 groups identify tile types, not red status; the original candidates retain red distinctions. No score, recommendation, hidden state or tool capability is added. Disabled messages and output schema are unchanged. `blind-discard-arena-hand-structure.test.ts` enforces bindings, failure, future-event separation and local decomposition semantics alongside the existing Arena tests.

## Optional standard improvement facts

`improvementFacts` is opt-in, requires the complete canonical candidate set, and rejects the mixed helper and callable tools. The main-owned adapter binds each row to its actionRef and case, projects decision-time facts, calls standard `analyzeHand13` and validates the response. Incomplete visibility, self riichi, and unknown riichi are explicitly unavailable; engine errors remain per-candidate errors. No theoretical remainder is presented as an unseen count.

Each case has an explicitly keyed dictionary of exact ordered `bestWaits` arrays, assigned in order of first appearance. Each candidate's complete ordered `improves` list retains draw tile, unseen draw copies, and dictionary key; zero copies and repeated data remain intact. These are ordinary/applicable-seven-pairs facts, not kokushi or a future discard witness, all ties, live-wall counts, probabilities, payoff or a candidate recommendation. No estimates or provider capabilities enter the packet. `blind-discard-arena-improvement.test.ts` protects row binding, dictionary integrity, failure and availability boundaries, and default-off behavior.

## Opt-in defense facts

`defenseFacts` uses the existing opponent-specific deterministic matrix and validated threat-risk classifier, with full case/action/opponent bindings. It is default off and may accompany `basicCalculations`; legacy mixed helper, active tools, structure/improvement, teaching, hints, comparisons and explanations are excluded in this intervention. Known genbutsu evidence survives incomplete response timing; absence of proof and all structural classifications are unavailable in that situation. Unsupported open threats remain explicit. Unseen honor counts are not live-wall counts, and suji/wall classifications do not guarantee safety. The existing engine internally computes its heuristic scale, but the packet excludes the scale, early-outside label and recommendations.
