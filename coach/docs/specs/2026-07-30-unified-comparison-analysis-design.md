# 统一候选比较与经验教学设计

日期：2026-07-30
状态：已通过对话设计评审，待书面复核
适用范围：Mortal/Akagi 牌谱复盘、对话中的真实或假设何切比较、证据约束型教练输出

## 1. 背景

现有严格推理核心能够重放可见事件、计算标准形向听、识别分玩家现物与一发状态，并用双向因素账本阻止 LLM 为模型动作事后编造原因。

下一阶段需要同时满足两种常见需求：

1. 牌谱复盘时，以 Mortal 或 Akagi 返回的候选动作与评分为正式分析依据；
2. 对话中没有模型评分时，允许用户提出真实或假设手牌，并限定两个或少量动作进行比较。

这两种需求不应发展成两套分析器。它们共享同一条“事实 → 计算 → 五轴账本 → 偏好 → 决定性理由 → 表达”管线。模型评分只是可选证据；候选动作的来源不同，不改变麻将事实和候选后果。

## 2. 目标

本设计的目标是：

- 使用同一套结构化比较管线处理模型候选、实战动作和用户指定动作；
- 允许用户在当前牌谱之外临时提出独立假设；
- 按题意决定分析范围，不把每道平面何切都扩张成实盘攻守题；
- 在没有模型评分时，用确定性计算和有来源的麻将经验形成有限结论；
- 分开保存模型偏好与教练偏好，允许二者冲突；
- 从同构候选账本中选择具体、可验证的决定性理由；
- 继续执行零模型因果归因、双向因素账本和失败关闭；
- 保持默认错误详解阈值为 10。

## 3. 非目标

本里程碑不负责：

- 枚举某局面的全部合法动作；
- 证明 Mortal/Akagi 返回了全部合法动作；
- 在无模型时搜索整棵动作树或保证找到全局最优动作；
- 推断对手暗手或对手的合法动作全集；
- 把模型分数解释为模型内部推理；
- 对用户没有给出的实盘条件逐项追问；
- 用 LLM 训练记忆伪造麻将书籍观点或引用。

模型候选集合是自动复盘的分析范围，不是合法动作证明。候选未出现只表示模型结果中没有它，不表示该动作非法。

## 4. 统一分析管线

```text
AnalysisFrame
  ├─ conceptual
  │    → TeachingEvidence 与规则事实
  │    → 受约束表达与验证
  └─ comparison
       → ComparisonSet
       → 逐候选确定性计算
       → 五轴同构账本
       → 可选 ModelEvaluation
       → TeachingEvidence 与教学规则
       → modelPreference / coachPreference / agreement
       → 决定性理由
       → 受约束表达与验证
```

### 4.1 AnalysisFrame

分析请求是判别联合：

- `comparison_request`：必须携带至少两个动作的 `ComparisonSet`；
- `conceptual_request`：禁止携带 `ComparisonSet`，直接进入规则事实、教学证据和受约束表达。

`AnalysisFrame` 是一次请求使用的事实边界。它必须属于以下一种：

- `current_scene`：使用发送消息时附带的当前牌谱局面；
- `modified_scene`：复制当前局面，并只应用用户本轮明确提出的修改；
- `standalone_hypothesis`：只使用用户本轮提供的假设条件；
- `conceptual`：规则或经验问题，不绑定具体局面。

优先级为：用户本轮明确表述高于隐藏上下文。该优先级只影响本次问题，不修改原始牌谱状态或后续浏览状态。

独立假设不得继承当前牌谱中的点数、巡目、牌河、立直、副露、宝牌或顺位信息。局面修改必须以不可变副本实现，不能污染原始事件重放结果。

每项局面事实保留 `raw_replay` 或 `user_asserted` 来源。用户对当前局面的修改必须同时保留被替换事实和修改来源，验证器才能检查上下文是否被意外混用。

### 4.2 题意范围

`AnalysisFrame` 同时保存题意范围：

- `flat_discard`：平面何切，关注牌形、向听、有效牌、改良、役和打点；
- `single_axis`：只分析用户指定的牌效、防守、牌河、顺位、鸣牌等轴；
- `applied_decision`：用户明确要求实盘综合判断，或题面明确给出实盘条件；
- `conceptual`：解释规则与经验。

未提供的条件默认不纳入当前题目，而不是逐项作为阻塞项报告。分析器只在题意相关且前置事实齐备时运行。

题意识别遵循以下优先级：

1. 用户明确指定“只看牌效”“考虑防守”“按实战综合”等范围时，以用户指定为准；
2. 只有“只看”“仅考虑”等明确闭域措辞才进入 `single_axis`；用户以“这里何切”等指代明确引用当前牌桌，或在何切问题中引用模型、实战动作、当前巡目、牌河、立直或点差而没有闭域措辞时，进入 `applied_decision`；
3. 独立假设只提供手牌和弃牌候选时，默认为平面何切；
4. 仅仅存在随消息附带的隐藏当前局面，不足以把问题自动扩张为实盘综合题；用户明确说“只看牌效”时始终覆盖隐藏实盘上下文；
5. 文字仍无法判定范围时，选择能回答问题的最小分析范围，不为补齐五轴而追问。

只有当用户预设结论与当前事实的确定性结果发生冲突时，才启动校准：

1. 先明确指出在现有题面下的计算结果；
2. 再询问是否遗漏了可能改变答案的牌河剩余枚数、对手立直、安全牌、点差或其他相关条件；
3. 不得替用户补造一个能够支持预设答案的情境。

## 5. ComparisonSet 与动作表示

每次局面比较必须有一个 `ComparisonSet`，包含至少两个处于同一决策层级的动作。纯概念问题不创建伪候选集合，直接进入规则事实与教学证据检索。

动作来源可以是：

- `model`：Mortal/Akagi 候选；
- `actual`：牌谱中的实战动作；
- `user`：用户提出的真实或假设动作。

### 5.1 动作类型

动作采用判别联合，而不是把字符串作为领域真相。首版契约能够表达：

- 普通弃牌；
- 立直弃牌；
- 吃；
- 碰；
- 大明杠；
- 暗杠；
- 加杠；
- 自摸；
- 荣和，包括抢杠语境；
- 九种九牌；
- 响应窗口中的 `pass`。

动作必须保留会改变麻将后果的身份：

- 赤五与普通五；
- 摸切与手切；
- 立直弃牌与普通弃牌；
- 吃碰所使用的具体牌组和红牌选择；
- 杠的种类、来源和既有副露引用；
- 荣和或 `pass` 所响应的事件。

业务逻辑不得依靠拆分 `discard:6s:tsumogiri` 一类字符串判断动作。字符串只用于稳定引用和显示。

### 5.2 规范化与一致性

`CandidateNormalizer` 负责把模型格式、牌谱事件和自然语言转换为统一动作对象。

系统不生成完整合法动作集合，只执行：

1. **规范化检查**：动作能否唯一转换成结构化形式；
2. **已知事实一致性检查**：动作是否与已有手牌和决策窗口明显矛盾；
3. **可比较性检查**：候选是否属于同一个决策层级。

信息不足时不得擅自判定动作非法。自然语言动作无法唯一解析时，只询问造成歧义的字段。

例如，“是否碰”与“碰后切哪张”属于两个连续决策，不得放进同一个 `ComparisonSet`。

### 5.3 自动复盘的评分要求

自动错误列表只有在以下条件同时成立时才生成分差：

- 模型首选存在且有评分；
- 实战动作存在且有评分；
- 两者均能唯一映射到当前 `ComparisonSet`；
- 分数口径已知且可比较。

缺少任一条件时，该决策不进入自动错误排名，也不生成基于模型分差的教练结论。用户仍可随后把相关动作作为普通限定比较题发问，由计算与教学经验处理。

自动复盘的 `ComparisonSet` 只由模型实际返回的已评分候选构成。若实战动作不能映射到其中，不创建自动 `ComparisonAnalysis`，只记录导入诊断。用户后续主动比较时，可以新建包含该实战动作的无评分 `ComparisonSet`。

## 6. 五轴候选账本

所有候选动作进入相同的 `FactorPipeline`，生成同构 `CandidateLedger`。五轴沿用《证据约束型日麻教练推理设计》：

- 牌效与速度；
- 打点与和牌质量；
- 防守与对手模型；
- 顺位与局收支；
- 可逆性与选择权。

分析器必须同时检查：

- 当前题意是否需要该轴；
- 当前事实是否满足该分析器的前置条件；
- 输出能否附带确定来源；
- 该因素支持哪个候选、反对哪个候选或无法区分。

跳过无关分析轴是正常行为。结构化结果保留已运行、因题意跳过、因信息不足跳过和暂未支持的状态，但正常对话不默认展示整份覆盖清单。

同一局面与同一候选的事实计算不能因是否存在模型评分而变化。删除 `ModelEvaluation` 后，候选账本必须逐字段保持不变。

## 7. 模型证据

`ModelEvaluation` 是可选字段，至少记录：

- 引擎与版本；
- 每个已评分候选的原始分数、原始口径和适配器版本；
- 用于界面和错误阈值的 0–100 `modelSelectionScore`；
- 模型首选；
- 实战动作；
- 可比较的分差；
- `modelReason: "unknown"`。

`modelSelectionScore` 沿用既有“模型选择分”契约：

```text
Mortal 模型选择分 = 结果页候选概率 × 100
Akagi 模型选择分 = 对本次返回候选 logits 计算的 softmax 概率 × 100
errorGap = modelSelectionScore(modelPreferredAction)
         - modelSelectionScore(actualAction)
```

默认阈值 10 表示同一次模型评估内的 10 个模型选择分点。`errorGap >= 10` 为详细解释，`errorGap < 10` 为一句具体简评。不得跨引擎、跨模型版本或跨决策比较该分差，也不得把模型选择分描述为胜率、打点或 EV。

分析会话冻结阈值、引擎版本、原始值、适配器版本和适配结果。用户修改全局阈值只影响新会话；旧会话只有通过显式重新分析才能改变分级。无法生成同口径分数时不计算错误分差。

模型评分只能证明偏好顺序和差距，不能证明原因。允许的表述是：

> Mortal 更偏向摸切 6 索；该动作相对切 2 筒具有对上家立直现物的安全优势。

禁止的表述是：

> Mortal 因为想避开一发，所以摸切 6 索。

## 8. 教学证据

### 8.1 证据层级

教练按四层处理信息：

1. **用户事实**：用户明确给出的手牌、动作和条件；
2. **确定性计算**：向听、有效牌、牌形、等待、役与可确定打点等；
3. **教学经验**：版本化教学规则或从登记资料、MCP 麻将书籍检索到的适用原则；
4. **教练表达**：对前三层进行压缩和解释。

第四层不得新增前三层不存在的牌局事实、数字或教学观点。

### 8.2 TeachingEvidence

每条经验依据形成 `TeachingEvidence`，至少包含：

- 稳定证据 ID；
- MCP 资源 ID、文档 ID 或其他稳定资源标识；
- 书名或资料名；
- 作者；
- 版本或版次；
- 章节、页码、段落或稳定定位信息；
- 支持当前教学断言的最小原文片段；
- 原文片段的精确内容哈希；
- 适用条件；
- 支持的候选或因素；
- 限制；
- 检索时间；
- 检索器版本；
- 从原文片段映射为结构化教学原则的规则版本。

初始来源登记在 `RESOURCES.md`，包括 Riichi Book I、Riichi Wiki、可复现向听实现和带统计口径的公开资料。未来接入的 MCP 麻将书库使用同一契约。

教材经验只能帮助衡量已经计算出的候选差异，不能凭空生成牌局事实。检索不到合适资料时，不允许退回 LLM 训练记忆伪造出处。远程或 MCP 来源必须把用于本次判断的最小原文片段冻结到证据注册表。

内容哈希固定为 `SHA-256(UTF-8(sourceExcerpt))`：`sourceExcerpt` 是检索器交给分析管线的精确 Unicode 字符串，不折叠空白、不替换标点、不做 Unicode 归一化或 OCR 修正。任何文本修订都形成新的证据快照。验证器使用同一字节口径校验，不依赖未来仍能访问同一外部资源。

资料规则的适用条件必须表示为可重算谓词集合。只有当规则 A 的全部条件满足当前题面，且 A 的条件集合严格包含规则 B 的条件集合时，A 才能被判定为比 B 更具体。若两套条件无法形成该包含关系，系统保留冲突，不产生经验偏好，也不由 LLM 自行投票。

## 9. 偏好解析

`ComparisonAnalysis` 分开保存：

- `modelPreference`：来自模型评分的非空动作集合，或 `null`；
- `coachPreference`：来自计算和教学规则的非空动作集合，或 `null`；
- `agreement`：`agree`、`partial_agreement`、`conflict` 或 `not_comparable`。

模型最高选择分并列时，`modelPreference` 保存全部并列动作。教练认为多个动作等价时，`coachPreference` 同样保存全部等价动作。

一致性使用固定真值表：

- 任一偏好为 `null`：`not_comparable`；
- 两个非空集合完全相等：`agree`；
- 两个非空集合有交集但不相等：`partial_agreement`；
- 两个非空集合没有交集：`conflict`。

### 9.1 教练偏好

`PreferenceResolver` 按以下顺序生成教练偏好：

1. 用户明确指定单轴时，保存该轴中全部并列最优动作；只有所有候选在该轴完全相同时才不形成偏好；
2. 多轴范围内，若一个非空候选组是 `ComparisonSet` 的真子集、组内动作具有完全相同的评估向量，且组内每个动作都在所有已实现且相关的可比较因素上不劣于组外每个动作，并至少在一个因素上严格更优，则保存该组为确定性支配偏好；
3. 多个确定性轴分别支持不同动作时，只能由适用条件完整、版本化且有来源的跨轴教学规则形成经验结论；
4. 确定性结果不足以取舍时，使用条件匹配且有来源的教学规则形成经验结论；
5. 仍无法区分时，`coachPreference = null`，并保留双向取舍。

若存在多个互不支配的极大评估向量，不把它们误写成并列偏好；除非跨轴教学规则解决取舍，否则 `coachPreference = null`。

无模型评分不等于无法分析；它只表示不能使用模型偏好和模型分差。系统不声称无模型教练偏好是全局最优动作。

### 9.2 模型与教练冲突

模型偏好与教练偏好可以冲突。冲突时必须并列保留，不能为了迁就模型删除反方因素或修改教练规则。

示例：

> Mortal 更偏向切 8 筒；但在当前只讨论平面牌效的题面下，确定性计算支持切 7 筒。牌谱中若存在攻守条件，需要另行纳入；系统不会替模型假定该原因。

## 10. 决定性理由

结构化结果不得使用“模型决定性理由”这一字段。它分开保存：

- `modelAlignedObservableFactors`：方向上与模型偏好一致的可观察差异，不表示模型因果；
- `coachDecisiveReasons`：确定性计算或教学规则实际用于形成教练偏好的理由。

两者都必须来自已经生成的差异因素。模型与教练冲突时分别保存，不能用一个理由同时冒充两种偏好的依据。选择顺序为：

1. 与用户问题直接相关；
2. 来源和计算确定性更高；
3. 对候选差异影响更大；
4. 能具体描述动作后果；
5. 与所表达的偏好方向一致。

对于包含多个动作的偏好集合，集合级同向因素必须至少支持一个集合成员相对一个集合外动作，且不得反对任何集合成员、不得用于区分集合内部的并列动作。不满足这一条件的因素只能保留在候选账本中，不能进入集合级理由列表。

模型分数不能标识模型的决定性原因。`modelAlignedObservableFactors` 只负责说明哪些可观察差异与模型排序方向一致，而不是还原模型内部思维。

若现有账本找不到与模型偏好方向一致的可靠因素，`modelAlignedObservableFactors` 为空，并必须写明当前已计算要素无法解释该分差。禁止挑选一个听起来合理但无证据的因素。

## 11. 输出策略

正常对话只输出结论和决定性理由，不展示完整思考链。结构化账本、跳过的分析轴、模型原始候选、教材证据和校验状态可在界面中展开审计。

### 11.1 有模型评分

- 分差大于或等于默认阈值 10：详细解释主要支持因素、重要反方因素，以及模型偏好与教练偏好是否一致；
- 分差小于 10：只输出一句具体麻将差异；
- 若没有可验证差异：明确说明无法从当前已计算要素解释分差，不输出空泛的“差距很小、实战可以理解”。

### 11.2 无模型评分

- 直接表达教练的计算结论、经验结论或无法可靠取舍；
- 不套用模型分差阈值；
- 默认不列出题面之外的未知条件；
- 教材经验作为决定性依据时，正文简短标注来源，完整定位信息可展开。

## 12. 模块边界

- `FrameResolver`：建立事实边界与题意范围；
- `CandidateNormalizer`：统一模型、实战和用户动作；
- `FactorPipeline`：运行相关分析器并生成同构候选账本；
- `ModelEvidenceAdapter`：导入可选模型评分，不参与事实计算；
- `TeachingEvidenceRetriever`：查询版本化规则与 MCP/登记资料；
- `PreferenceResolver`：生成模型偏好、教练偏好和一致性状态；
- `ReasonSelector`：分别选择模型同向可观察因素和教练决定性理由；
- `ExplanationValidator`：拒绝无证据事实、数字、原因和引用。

每个模块通过明确契约通信。事实计算模块不得读取模型首选；教学检索模块不得修改候选计算；表达层不得绕过偏好与证据结构直接读取原始牌谱。

### 12.1 实施分解

本文件是统一架构规格，不对应一个不可审查的单体实现计划。实施按以下顺序拆成可独立验收的切片：

1. `AnalysisRequest`、`AnalysisFrame`、`ComparisonSet`、偏好集合、选择分与阈值契约；
2. 完整动作判别联合与 `CandidateNormalizer`；
3. 统一 `FactorPipeline`、确定性支配和冲突解析；
4. `TeachingEvidence`、资料/MCP 检索、证据冻结和来源冲突处理；
5. 对话编排、理由选择、输出模板和全量验证器。

书面复核本规格后，先为切片 1 编写实施计划。后续切片在进入实现前，从本架构规格中提取各自的范围规格并独立复核，避免一次计划同时改变所有子系统。

## 13. 失败处理

- 自然语言动作无法唯一解析：只询问该处歧义；
- 某分析轴不属于题意范围：静默跳过；
- 某分析轴缺少前置事实：该轴不参与结论，其他轴继续；
- 某分析器运行失败：记录失败状态，禁止使用该轴的因素；
- 教材检索无结果：不生成经验依据；
- 模型候选或评分不完整：不进入自动错误列表；
- 模型动作与已知局面明显矛盾：标记导入或重放错误；
- LLM 引用不存在的事实、数字、因素或资料：拒绝并最多重试两次；
- 两次生成仍失败：退回确定性模板；
- 教练规则无法形成偏好：允许输出“当前条件下无法可靠取舍”。

## 14. 验收测试

### 14.1 真实牌谱回归

牌谱 `260730-8649addb-b4cb-48e1-ba8e-c6c3ffbb9166_a62115198`：

- 东一局 6 巡继续重建为牌效支持切 2 筒、防守支持摸切 6 索；
- 东一局 7 巡继续重建为牌效支持切 7 筒、防守支持切 8 筒；
- 不得生成“6 索是牌效冗余张”或“切 8 筒保留更好牌形”；
- `modelReason` 始终为 `unknown`。

### 14.2 统一管线变形测试

- 删除同一比较的模型评分后，`AnalysisFrame`、确定性计算、候选账本和因素必须完全不变；
- 添加模型评分后，只允许新增模型偏好、分差、详略级别、一致性状态和 `modelAlignedObservableFactors`；`coachPreference`、`coachDecisiveReasons`、候选账本和原有因素必须不变；
- 模型偏好与教练偏好冲突时，两者必须同时保留；
- 模型偏好与教练偏好冲突时，模型同向可观察因素与教练决定性理由必须明确分开；
- 不同引擎的原始分数不得绕过适配器直接参与阈值比较；
- 模型候选中没有某动作时，不得把该动作描述为非法；
- 自动复盘缺少实战动作评分时，不得生成错误分差。
- 实战动作不在模型已评分候选中时，不得创建自动 `ComparisonAnalysis`，但应保留导入诊断；
- `errorGap` 为 `9.999`、`10`、`10.001` 时，分别进入简评、详解、详解；
- 会话创建后修改全局阈值或适配器版本，不得悄然改变旧会话分级。

### 14.3 对话分析帧测试

- 只给手牌的平面何切题不得自动输出防守、点差或牌河未知项；
- 当前牌桌只问“这里何切”时使用实盘范围；明确说“只看牌效”时收窄为平面范围；
- 仅附带隐藏当前局面但问题未引用它时，不得仅凭隐藏上下文扩张题意；
- 独立假设不得继承当前牌谱隐藏上下文；
- 当前局面的临时修改不得改变原始重放状态；
- 用户预设答案与确定性牌效冲突时，必须先指出冲突，再询问可能遗漏的相关条件；
- 没有冲突时不得为补齐五轴而连续追问；
- 概念题不得被强行转成实盘局面分析，且其请求中必须没有 `ComparisonSet`。

### 14.4 动作契约测试

- 赤五与普通五不能合并；
- 摸切与手切不能合并；
- 立直弃牌与普通弃牌不能合并；
- 不同吃牌组合和红牌用法不能合并；
- 吃、碰、杠、自摸、荣和、九种九牌和 `pass` 能稳定往返序列化；
- 不同决策层级的动作不能进入同一 `ComparisonSet`。

### 14.5 教学证据测试

- 每条教材经验都能定位到来源；
- 来源不可用时不得保留相应经验结论；
- 来源内容与适用条件不匹配时不得引用；
- 两个来源冲突时保留冲突或使用更具体匹配规则，并记录选择依据；
- 两套适用条件无法形成严格包含关系时不得擅自判断哪条更具体；
- MCP 内容哈希变化时旧证据不得被静默替换；
- MCP 暂时不可用时，只能使用哈希验证通过的冻结证据片段；
- 固定字符串测试向量必须验证 `SHA-256(UTF-8(sourceExcerpt))`，并证明空白、标点或 Unicode 字符变化会产生新快照；
- LLM 伪造书名、页码、统计口径或观点时被验证器拒绝。

### 14.6 输出测试

- 分差小于 10 的说明必须包含具体麻将差异；
- 分差大于或等于 10 时同时展示主要支持因素和重要反方因素；
- 没有可靠支持因素时输出“当前已计算要素无法解释”，不得编造原因；
- 无模型时能输出计算结论、经验结论或无法可靠取舍；
- 两个确定性分析轴分别支持不同动作，且没有跨轴教学规则时，`coachPreference` 必须为空；
- 任一偏好为空、偏好集合相等、部分重合和完全分离时，`agreement` 必须分别符合固定真值表；
- 默认正文不泄露完整思考链或内部账本；
- 所有可见断言均能回指结构化证据。

### 14.7 验证器重算

验证器必须从可信输入重新计算：

- `AnalysisFrame` 的事实边界和题意范围；
- 候选动作规范化与映射；
- 确定性候选结果；
- 五轴账本与双向因素；
- 模型偏好和分差；
- 教练偏好及引用的教学规则；
- 决定性理由；
- 教材引用；
- 最终确定性解释。

任何附加隐藏字段、篡改数值、越权因果归因或不存在的引用都必须导致验证失败。

## 15. 验收标准

1. 模型复盘与无模型限定比较共用同一条分析管线；
2. 模型评分是可选证据，不改变麻将事实和候选账本；
3. 用户可以在对话中提出任意真实或假设手牌；
4. 分析范围由题意和已给事实决定；
5. 缺失条件默认不参与，不自动扩张成实盘综合题；
6. 只有预设结论与确定性结果冲突时才校准额外条件；
7. 模型候选不被称为全部合法动作；
8. 不遍历无模型局面的完整合法动作树；
9. 模型偏好与教练偏好分开保存并允许冲突；
10. 无模型时可以由确定性计算或有来源经验形成有限结论；
11. 教材经验具有可审计来源和适用条件；
12. 决定性理由只能来自候选账本；
13. 默认阈值 10 的详略规则继续生效；
14. 简略解释仍包含具体麻将原因；
15. 当前局面、局面修改和独立假设之间不存在上下文污染；
16. 东一局 6、7 巡回归继续通过；
17. LLM 无法通过自由文本绕过证据、偏好和引用校验。

## 16. 与既有规格的关系
