## 1. 问题与目标

麻将模型输出动作、候选分数和概率，但不输出可验证的内部推理。仅把牌局 JSON 和模型首选交给 LLM，会诱使 LLM 事后编造一个听起来合理的理由。

真实牌谱 `260730-8649addb-b4cb-48e1-ba8e-c6c3ffbb9166_a62115198` 暴露了这一缺陷：

- 东一局 6 巡，纯牌效应切孤张 2 筒并保留 `456789` 索两个完成面子；上家刚以 6 索立直，Mortal 却以 99.28% 推荐摸切现物 6 索。旧解释错误地把 6 索称为牌形冗余张。
- 东一局 7 巡，纯牌效下 `6778` 筒应切一张 7 筒，固定对子和 `678` 面子；Mortal 推荐切 8 筒。该动作与继续使用对立直者现物一致，但系统不得据此推断 Mortal 的内部原因。旧解释错误地声称切 8 筒能保留更好牌形。

本设计的目标不是猜中麻将模型的隐藏原因，而是：

1. 尽可能完整地重建决策瞬间的立直麻将局面；
2. 确定性或带来源地计算每个候选动作的可观察后果；
3. 同时列出支持模型动作与支持实战动作的因素；
4. 使用公开、可审计的教学规则给出教练自己的建议；
5. 明确把模型事实、计算结果、教学判断和未知事项分开；
6. 让机器能够验证每项断言的来源，而不是判断一段自由文本是否“懂麻将”。

## 2. 核心原则

### 2.1 零模型因果归因

系统不得声称知道 Mortal 或 Akagi 的内部原因。

允许：

> Mortal 推荐摸切 6 索。与切 2 筒相比，6 索对上家立直是现物，但会牺牲牌效。按教练规则 PF-03，本局面建议优先防守。

禁止：

> Mortal 因为想防守，所以选择 6 索。

所有结构化解释都必须将 `model_reason` 固定为 `unknown`。模型动作与模型分数是原始事实；“与某项因素一致”不等于“模型因为该因素而行动”。

### 2.2 双向因素账本

系统不得只挑选支持模型首选的因素。每次比较必须同时保存：

- `supports_model_action`：方向上支持模型动作的因素；
- `supports_actual_action`：方向上支持实战动作的因素；
- `neutral_factors`：两动作无可观测差异的因素；
- `unknown_or_unmeasured`：尚无可靠算法或证据不足的因素。

这能防止在要素越来越丰富后，对任何模型动作进行事后合理化。

### 2.3 严格证据模式

- 事实缺失时不生成对应断言；
- 无法可靠计算时输出未知，不用 LLM 补全；
- 启发式结果必须显示来源、置信等级和限制；
- 任何数字必须携带口径；
- 解释生成失败时，退回确定性模板，而不是放宽校验。

### 2.4 教练规则可审计

教练结论来自有编号、可版本化的教学规则。规则只组合已经生成的因素，不直接读取原始牌谱，也不输出自由文本原因。

如果教学判断有问题，应修改规则定义、资料依据和回归测试，而不是增加新的 Prompt 话术。

## 3. 三层判断系统

### 3.1 第一层：局面事实

事件重放器从完整 mjai 事件流冻结决策瞬间，至少产生：

- 场风、局数、本场、立直棒、剩余牌数；
- 四家点数、顺位、点差、亲家和自风；
- 四家牌河，保留手切、摸切、被鸣牌和立直宣言牌；
- 四家副露、立直状态和一发窗口；
- 我方手牌、当前摸牌、振听和合法动作；
- 宝牌指示牌、宝牌、赤牌与所有公开已见牌；
- 每个事实对应的事件 ID。

事件映射失败或关键字段缺失时，该决策标记为 `incomplete_scene`，不得生成完整原因。

### 3.2 第二层：五条分析主轴

#### 牌效与速度

- 普通形、七对子和国士无双向听数；
- 完成面子、雀头、搭子、浮牌和五区块；
- 直接有效牌及扣除公开牌后的剩余枚数；
- 二次改良、最终等待质量和振听；
- 吃碰杠对向听、有效牌、可和役与剩余巡目的影响；
- 听牌、和牌和流局听牌的速度价值。

#### 打点与和牌质量

- 已确定役、潜在役和役丢失风险；
- 宝牌、赤牌、里宝牌机会和杠宝牌变化；
- 立直、默听、副露与门清价值；
- 符番范围、亲子差异和最低/典型打点区间；
- 等待枚数、等待种类、振听和可荣和性；
- 打点提升所付出的速度、安全和选择权代价。

#### 防守与对手模型

- 立直者、亲子、立直巡目、宣言牌和一发状态；
- 明显高速度或高价值副露；
- 对每名威胁者分别计算的现物、筋、壁、one-chance、字牌可见枚数和无筋；
- 多家威胁下每张牌的分对象安全性；
- 对手可能牌型、价值与等待范围的牌河推测；
- 放铳后果和同时面对多家时的风险组合。

牌河阅读分四级：

1. `deterministic`：现物、宣言牌、手切/摸切、鸣牌组成和公开牌；
2. `structural_heuristic`：筋、壁、one-chance、字牌枚数等结构安全；
3. `behavioral_heuristic`：染手、对对和、役牌、宝牌周边、手切序列等牌型推测；
4. `wait_heuristic`：跨筋、里筋、间四间、立直前后手切等等待推测。

第 3、4 级不得描述为确定事实。

#### 顺位与局收支

- 当前点差、目标名次和剩余局数；
- 亲家连庄、终局条件和西入条件；
- 立直棒、本场与听牌罚符；
- 和牌、放铳、被摸、流局听牌和流局未听对顺位的直接影响；
- 可接受失点、必须和牌、只需听牌或应避免立直棒损失等目标；
- 多个结果路径对目标名次的敏感性。

#### 可逆性与选择权

- 立直、鸣牌和杠带来的不可逆性；
- 当前及未来安全牌库存；
- 回旋打是否能保持向听或有效牌；
- 未来进攻、默听、立直和弃和之间的切换能力；
- 临时振听、永久振听和危险牌后置；
- 信息价值与等待下一巡再决策的价值。

### 3.3 第三层：候选动作账本

每个合法候选动作产生同构的 `CandidateLedger`，记录它在五轴上的后果。系统比较模型动作与实战动作，生成双向因素账本，不先把所有维度压成一个无法审计的总分。

主轴不是模型意图，而是当前候选差异中证据最完整、影响最显著的教学维度。多个维度接近时保留多个主轴，不强行选择唯一原因。

## 4. 统一证据契约

每项分析因子使用统一结构：

```json
{
  "factor_id": "factor:e1:turn6:safety:6s:actor2",
  "axis": "defense",
  "dimension": "genbutsu",
  "subject_action": "discard:6s:tsumogiri",
  "comparison_action": "discard:2p:tedashi",
  "direction": "supports_subject",
  "magnitude": {
    "kind": "ordinal",
    "value": "decisive"
  },
  "statement": "6索是对actor 2立直的现物；2筒没有已验证的安全依据",
  "provenance": "deterministic",
  "confidence": "certain",
  "evidence_ids": ["event-47", "event-48", "event-50"],
  "limitations": ["只保证对actor 2安全，不保证对其他玩家安全"]
}
```

`provenance` 只能是：

- `raw_model`：分析引擎原始动作或分数；
- `raw_replay`：牌谱原始事件；
- `deterministic`：由规则和完整状态确定性计算；
- `derived_heuristic`：启发式估计；
- `calibrated_statistic`：具有明确数据集和校准口径的统计模型；
- `teaching_rule`：版本化教练规则；
- `unknown`：无法可靠判断。

KillerDucky 结果页的危险条不是 Mortal JSON 原始输出。其前端通过 `calcDanger()`、未见牌、现物和一组启发式等待权重派生危险度；这些值只能标为 `derived_heuristic`，不得称作 Mortal 铳率或校准放铳概率。

## 5. 因素分析器与覆盖清单

系统由多个职责单一的分析器组成：

- `SceneReplayer`：重放事件并冻结场景；
- `HandStructureAnalyzer`：向听、区块、有效牌和等待；
- `ValueAnalyzer`：役、宝牌和打点区间；
- `ThreatAnalyzer`：立直、副露与多家威胁；
- `TileSafetyAnalyzer`：分对象安全等级；
- `RiverInferenceAnalyzer`：牌河与牌型启发式；
- `PlacementAnalyzer`：点差、终局条件和结果路径；
- `OptionValueAnalyzer`：安全牌库存和不可逆性；
- `ActionComparator`：产生双向因素账本；
- `TeachingPolicyEngine`：用版本化规则生成教练建议。

每个分析器声明：

- 支持的规则和牌局类型；
- 所需输入；
- 输出因子；
- 来源与置信等级；
- 无法分析时的明确状态；
- 单元测试与真实牌谱夹具。

覆盖清单列出判断体系中的全部细分项，并标注 `implemented`、`heuristic`、`unsupported` 或 `blocked_by_missing_data`。未实现的要素保留在体系中，但不能由 LLM 代填。

## 6. 教练推理协议

每个决策严格按以下顺序处理：

1. 固定实战动作、模型动作和原始模型分数；
2. 确认场上威胁和顺位目标；
3. 为全部合法动作生成五轴候选账本；
4. 比较模型动作与实战动作；
5. 输出支持双方、无差异和未知因素；
6. 运行教学规则，产生教练自己的建议；
7. 生成受约束的教学表达；
8. 验证所有断言的来源和措辞。

核心解释由确定性模板生成。LLM 可以：

- 调整教学表达；
- 根据同一证据包回答追问；
- 解释公开教学规则；
- 指出多个因素之间的取舍；
- 明确说明未知和限制。

LLM 不得：

- 新增证据包中不存在的麻将事实；
- 声称知道模型内部原因；
- 把启发式危险度写成精确铳率；
- 隐藏支持实战动作的反方因素；
- 把退向听或拆完成面子的动作解释为纯牌效优势；
- 把对一家的现物写成全场安全；
- 在规则未覆盖时自行补出教学结论。

## 7. 教练输出契约

```json
{
  "decision_id": "e1-turn6-discard",
  "model_fact": {
    "engine": "Mortal 4.1b",
    "recommended_action": "discard:6s:tsumogiri",
    "recommended_score": 99.28,
    "actual_action": "discard:2p:tedashi",
    "actual_score": 0.01,
    "model_reason": "unknown"
  },
  "observed_tradeoffs": {
    "supports_model_action": ["factor:e1:turn6:safety:6s:actor2"],
    "supports_actual_action": ["factor:e1:turn6:efficiency:2p"],
    "neutral_factors": [],
    "unknown_or_unmeasured": ["calibrated_dealin_probability"]
  },
  "primary_axes": ["defense", "efficiency"],
  "coach_judgement": {
    "recommended_action": "discard:6s:tsumogiri",
    "rule_ids": ["PF-03"],
    "confidence": "high"
  },
  "deterministic_explanation": "纯牌效支持切2筒；安全度支持摸切6索。按PF-03，本教练在上家立直的一发巡，以低价值远听手优先选择对上家现物6索。无法知道Mortal的内部原因。"
}
```

界面默认展示教学文字，并允许展开：

- 模型原始候选；
- 支持模型动作的因素；
- 支持实战动作的因素；
- 教学规则全文和版本；
- 各危险度的来源与限制；
- 未覆盖的分析项。

## 8. 教学规则体系

规则按五轴组织，不按具体牌谱堆叠特判。每条规则包括：

- 稳定规则 ID 和版本；
- 适用条件；
- 所需因素；
- 支持与反对条件；
- 输出建议；
- 置信等级；
- 资料来源；
- 反例与限制；
- 测试夹具。

规则只允许引用因素，不允许读取昵称、特定牌谱 ID 或模型首选，以避免为模型答案量身定制。

首个真实牌谱回归规则定义为：

### PF-03@1：立直一发巡的远听防守

仅当以下因素全部成立时适用：

- 至少一名对手已经立直，当前仍在其一发窗口；
- 我方为两向听或更远；
- `ValueAnalyzer` 未产生足以支持强攻的高价值因子；
- `PlacementAnalyzer` 未产生必须和牌、必须听牌或必须争取连庄的强攻因子；
- 合法候选中存在对该立直者的确定现物。

存在高价值或顺位强攻因子时，PF-03 不给出结论，交由能显式比较收益与风险的规则处理。面对多名威胁时，必须逐家比较安全性，不能因某张牌对一人是现物就直接应用。

适用时，规则先选择对当前主要威胁具有确定安全依据的候选；多个候选安全等级相同时，再按牌效损失和未来安全牌库存排序。只有局面完整且所需因素均为 `deterministic` 或 `raw_replay` 时才能输出高置信建议；否则降为未知，不得由 LLM 补足。

规则体系参考现代立直麻将常见的攻守输入：我方向听与价值、对手威胁、待切牌危险度、巡目、点差与顺位。统计资料必须保留样本、规则和条件，不能把总体平均值当作个别对手在当前局面的精确概率。

首版资料基线：

- Daina Chiba，《Riichi Book I》：牌效、立直、攻守和牌桌判断顺序；
- 小林聡，2016 年天凤凤凰桌逐巡向听/听牌/和了统计：巡目条件；
- 小林聡，2023 年天凤凤凰桌总体统计：现代赤牌规则总体基准；
- ネマタ／雀Key会，赤牌规则立直平均点资料：亲子威胁必须分开；
- KillerDucky Reviewer 前端危险度算法：仅作为启发式实现参考，不作为校准统计。

## 9. 失败处理

- 决策与事件无法一一映射：`incomplete_scene`，不生成原因；
- 某分析器失败：保留其他轴，失败轴进入 `unknown_or_unmeasured`；
- 风险算法不可用：允许显示现物等确定事实，不显示危险度数值；
- 教学规则没有覆盖：只展示双向因素账本，不给出教练推荐；
- LLM 输出引用不存在的证据、改变数值或越权推断：拒绝并最多重试两次；
- 两次失败：使用确定性模板；
- 任何重试不得更改模型动作和原始分数。

严格模式下，“当前证据不足以可靠解释或给出教学建议”是有效输出。

## 10. 测试设计

### 10.1 真实牌谱回归

使用本次 Mortal 报告的脱敏固定夹具：

- 东一局 6 巡必须重建上家以 6 索立直、当前一发窗口和我方摸入 6 索；
- 切 2 筒必须记录为牌效更优的一侧；
- 摸切 6 索必须记录为对上家安全度更优的一侧；
- 不得生成“6 索是牌效冗余张”；
- 东一局 7 巡必须记录纯牌效支持切 7 筒、对上家安全度支持切 8 筒；
- 6、7 巡的 `model_reason` 都必须为 `unknown`。

### 10.2 变形测试

- 删除上家立直事件后，现物和一发因素必须消失；
- 更换立直者后，现物归属必须随之改变；
- 删除上家的 8 筒牌河后，7 巡不得继续把 8 筒标记为现物；
- 推荐动作退向听时，不得产生“牌效更优”因子；
- 同一牌对一家现物、对另一家无筋时，必须分别记录；
- 未实现牌河推测时，必须返回 `unsupported`，不得补写推测。

### 10.3 契约测试

- 每个事实断言都能解析到证据 ID；
- 每个教学判断都引用现存规则 ID；
- 模型原因固定为未知；
- 所有危险度都带来源；
- 启发式数值不得使用“精确铳率”措辞；
- 双向因素列表均由同一候选账本生成；
- LLM 删除反方因素、改变数值或新增事实时被拒绝。

### 10.4 全盘一致性扫描

对固定牌谱中全部立直后决策运行：

- 场景重建完整性；
- 现物归属；
- 一发状态；
- 推荐与实战动作的向听和安全度差异；
- 解释来源完整性；
- 禁止模型因果归因。

测试不声称证明麻将模型的内部原因，只证明系统没有越过证据边界。

## 11. 验收标准

1. 教练不再声称知道 Mortal 或 Akagi 的内部原因；
2. 每个决策都有五轴覆盖状态；
3. 每个候选动作使用同构账本；
4. 同时展示支持模型与支持实战的因素；
5. 牌河阅读包含确定、结构、行为和等待四级；
6. 现物始终指明对应玩家；
7. 启发式危险度不冒充模型输出或校准概率；
8. 教学判断只能来自版本化规则；
9. 规则未覆盖时允许不给建议；
10. LLM 只能表达证据，不能创造核心原因；
11. 东一局 6、7 巡回归夹具通过；
12. 全盘立直后决策不存在已知的证据边界违规；
13. 用户可展开审计模型事实、派生因素、教学规则和未知项；
14. 新增分析要素通过统一因子契约接入，不修改 Prompt 来堆叠特判。
