# libriichi 唯一合法动作来源重构规格

日期：2026-09-28
状态：方向已批准，唯一来源已接入，验收按候选提交记录；规划基线 `67e1dd9c151c3fa1d9b66f14352c9c8721f60286`
决策来源：用户本线程明确要求；权威裁定：[ADR-0006](../adr/0006-libriichi-single-legal-action-authority.md)。

## 1. 目标与交付边界

将 libriichi 作为唯一合法动作来源，剥离并封存自建合法动作推导代码，取消第二动作
来源独立检错设计。范围包含 local runtime、remote report、self/response 开窗、
候选规范化、单候选、discovery、full-game 和 package 的相关消费者。
本规格最初为文档规划；已退出职责、替代入口和剩余问题见实施计划及封存清单。

保留 helper 的候选后果分析、结构/向听/进张/评分/防守事实和现有教学管线。
保留 canonical 源映射、实际事件校验、玩家可见性、来源身份及模型分数隔离。
不重写完整规则引擎、不增加新 workspace 包或通用 provider registry；不修改
Review Loop、admission、历史评审结果、Controller ledger/check 或保护规则。
R14 的 11 项发现已落实到实现与回归，具体证据见实施计划；设计变更本身不能证明通过，
后续候选仍须运行完整验证及独立验收。

## 2. 语义与职责

| 产物 | 含义 | 生产者 → 消费者 |
|---|---|---|
| canonical 事实/事件前缀 | 原始牌谱还原到此刻的可见信息 | source/replay → 规则输入投影与事实分析 |
| 待判定时点 | 摸牌、吃碰后弃牌、立直阶段、他家舍牌/杠等事件边界；不预断合法动作 | replay → libriichi |
| 合法动作结果 | 一个时点在固定规则下的全部可选动作，或明确失败原因 | libriichi 经严格转换 → 请求、豁免、覆盖账本 |
| 评价请求 | 为同一合法集合取得 Q 值；不是合法性查询或审批 | reasoning 投影/main 调度 → Mortal 网络 |
| 单候选证明 | 成功结果恰有一个动作且实际行动对应；可省略模型评分 | 合法动作结果派生 → full-game |
| 候选因素事实 | 每个动作的向听、进张、打点等后果 | helper/现有事实管线 → 教学分析 |

目标数据流：

```text
原始牌谱 → canonical / 可见状态 / 全部待判定时点
             → 完整性与规则配置核验
             → libriichi 规则查询（不加载 checkpoint）
             → 一个绑定身份的合法动作结果
                ├─ 多候选 → Mortal 评分或 remote report 绑定
                ├─ 单候选 → 有来源的无模型行证明
                └─ 失败 → 明确原因，不发豁免
             → 既有 full-game / StructuredAnalysisPackage
每个候选 → helper 因素分析 → 同一 package
```

事件边界扫描不得以自建吃碰/和牌牌形判断作为前置过滤，否则唯一规则来源仍会漏收
窗口。扫描所有适用边界，由 libriichi 决定是否存在选择；明确的非行动时点单独记账。
合法集合为零不能自动解释为单候选：非行动时点须有明确状态，预期行动窗口的零集合为错误。
用户指定何切候选可以作为分析输入，但不能被宣称为另一个完整合法集合；如果需要
实盘合法性保证，仍向同一规则组件查询。信息不足的概念比较保留其非实盘语义。

## 3. 规则输入、失败与唯一来源

- 复用固定 libriichi revision/native hash，记录明确的规则配置身份。逐项核验原
  wave-1 窗口、立直宣言/受理阶段、赤牌、杠、振听和响应历史与引擎的兼容性。
- 输入仅来自 canonical；不得用报告内嵌日志、实际选择、下一事件的未知信息或
  神经网络结果补全决策前状态。过去无响应的关闭事件与振听更新应按引擎协议准确
  重放，不可因牌谱未显式写 pass 就跳过历史。
- 完整性门只验证必要字段/事件历史可用与支持配置，不做一份替代规则计算。
  禁止余牌、全桌杠历史或响应历史 unknown 默认为 complete；无需知道对手暗牌。
- 若固定上游不能表达某项原有规则，记录具体兼容缺口并解决，不得把已支持合法
  场景统一降级、取交集或用本地 guard 补成第二规则来源。
- 规则查询失败会阻断该窗口规则结论；helper 失败只按既有因素分析契约反映，
  不能反向改变合法集合；模型失败不改变已获得的规则/事实结果。
- `coverageRegistry` 与真实 E2E 分支登记只用于验收样本统计及覆盖缺口报告。
  某分支尚无真实运行时验收记录，不得把已绑定且通过 libriichi/actual/候选面校验的
  动作标成 `unsupported_action`，也不得阻止其进入生产 review；验收 runner 仍独立记录
  并裁定分支覆盖。生产动作权威只看绑定成功的 libriichi 结果，不由验收登记构造合法集。
- 此语义变更会改变新分析的结果身份：生产 `componentVersions.factorPipeline` 升至
  `factor-pipeline/v2`，使重分析生成不同 `packageId`。已保存的 v1 package 保持原样，
  仍可按其原结果只读打开；不得就地重标其决策状态。
- 不保留自建全集作为生产兜底或常态测试 oracle。发现库与有依据的规则案例冲突
  时保留失败并定位，不通过篡改期望值让它通过。

## 4. 契约与身份

在 contracts 现有 runtime 契约内增加显式的规则查询操作与结果，升级协议/adapter
版本，不把 v1 model response 静默解释为规则证明。具体类型名在实施时沿仓库命名。

成功结果必须绑定：canonical stream 内容哈希、所消费事件前缀哈希、round/actor/
trigger/window/phase、规则配置、libriichi revision/native artifact、转换版本；
完整 canonical 动作、物理牌消费与模型编码关系；以及由这些内容派生的结果身份。
失败结果携带固定错误类别，无成功候选或豁免。所有响应校验完整请求关联，不能仅
使用 gameId/eventId。缓存键含全部上述影响语义的输入，仅缓存成功结果。

动作转换是表示转换，不是候选推理：吃碰消费牌、赤牌、摸切/手切、立直两阶段、
多个杠选择均须可唯一对应。若现有粗粒度 mask 不足，扩展从同一 libriichi 状态
导出的结构化动作信息，不让 TypeScript 再枚举合法组合填补。不支持隐式合并。
实际动作只在完整集合形成后做既有 realization correspondence 检查。

评分请求引用规则结果身份和候选身份；runtime 校验投影与结果一致，返回每项分数。
canonical actionRef、runtime index/variant、MJAI JSON 必须逐项对应，禁止交换
两项表示后只凭集合相等通过。重复、缺失、额外、跨窗口、非有限分数、错误 preferred
继续失败。模型 mask 与规则集合一致是同源编码一致性验证，不再声称独立规则检错。

规则来源在 StructuredAnalysisPackage 中单独可追溯，与 checkpoint/modelTag 分开。
无评分时仍可保存规则与分析事实；评分不可成为它们的权威。新旧 proof/package
版本显式区分：旧包按旧 schema 只读验证，不事后添写 libriichi 来源；新包不得接收
旧枚举生成的 proof。具体版本升级与兼容 fixtures 在契约切片一同落地。

## 5. 执行边界与所有权

mortal-runtime 保留既有特权 owner，提供规则查询与推理两类窄能力，lazy load 模型。
规则查询只需要已验证 native/执行器资产，不要求 checkpoint、torch 推理或网络。
native 加载路径与依赖均须受 manifest 约束，不能降低现有加载/超时/清理安全要求。
desktop main 注入规则端口；reasoning 的 replay/分析代码不能直接启动 native 进程。
不新增包依赖边；shared helper sidecar 的身份、协议和进程仍独立。

remote report 新分析也经同一规则端口建立期望窗口与集合，再绑定报告评分；缺本地
规则资产明确不可分析，不能恢复自建枚举或拿报告自己证明自己。保留独立原牌谱。
discovery 可以仅按事件扫描粗略搜样本，但不得宣称这些扫描命中就是合法动作；
需要合法性筛选时调用同一规则端口，仍不运行神经网络、不提交远端报告。

## 6. 封存与迁移策略

详细路径/符号见[实施计划](../plans/2026-09-28-libriichi-legal-action-authority-migration.md)。
封存采用固定 Git 基线加清单，不复制可执行旧代码到仓库 archive 目录；恢复历史须显式
读取历史对象，不暴露产品开关。混合文件先抽离保留的身份/格式/事实功能，再删规则分支。
当前基线不是回退指令，实施时必须重新核对后续改动并更新精确删除清单。

新端口可先独立验证，但产品切换要覆盖 replay→请求/豁免→full-game→package
以及 remote/discovery；不能只替换 selfCandidates 后保留别处第二判定。
迁移中临时旧实现明确标为待移除，不得成为验收终态或自动 fallback。

## 7. 完成标准

1. 每个适用事件边界都送到唯一规则来源；不存在旧牌形预筛导致的漏窗。
2. 无 checkpoint 的真实 libriichi 能产出规则结果；变更模型评分不改变它及因素事实。
3. 同一输入更换实际选择不改变未选动作；宣言/受理/响应窗口和赤牌/多杠身份正确。
4. 缺失事实/不兼容规则/引擎失败都不产生假单候选或伪完整集合。
5. 请求、豁免、coverage 只消费同身份结果；评分交换、跨内容回复等负例均拒绝。
6. local、remote、新旧包兼容路径及 helper 因素回归均验证；原支持范围无缩水。
7. 旧合法动作代码从运行、构建、导出、默认测试和打包依赖图退出；Git 封存清单完整。
8. R10–R14 行为反例保留；R14 全 11 项逐一复现/修复/验证，不以重构替代无关修复。
9. 五门、diff 检查、真实规则查询和最终提交绑定 CPU spike 按 VERIFICATION 执行。
   逐例聚合失败，明确 degraded 的原因；不继承旧 PASS，不把一致性称为穷举证明。

## 8. 变更控制记录（规划）

必要影响：contracts 协议/proof/provenance；runtime 规则执行与生命周期；reasoning
开窗/转换/汇总；desktop main 接线；spike/discovery 和对应测试。source mapper 仅在
已证明缺失必要 canonical 事实时修改，不预先重写。helper 只清理失去消费者的合法性
适配片段，不动有教学消费者的计算。新增概念只有版本化规则结果，归现有 contracts，
用于消除多处独立判定与身份歧义；模型评分不能表达无评分的单候选证明，故不能折入它。

改为唯一规则结果守恒。旧边界检查部分已强制，唯一来源与封存隔离尚属文档约定，
待实现补入现有 checker/行为测试后才可标机器强制。本规划未执行新运行时验证。
