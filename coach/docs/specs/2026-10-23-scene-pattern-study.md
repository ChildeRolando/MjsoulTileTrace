# 场景模式与 RAG 首轮试验

状态：离线工程实现与开发校准；正式有效性结论必须等待预标注和盲评。

## 范围与边界

四人日麻半庄的弃牌选择，保留完整四家公开信息。libriichi 仍是唯一合法动作来源；现有手牌事实引擎提供向听、等待及进张。模式只产生观察、研究问题和主题，不推荐行动，也不读取实际选择、输赢或 Mortal 标签。生产复盘、ReviewSession 和训练流程不变。

契约在 `packages/contracts/src/scene-patterns.ts`，纯函数与投影在 reasoning 的 `scene-patterns.ts`、`scene-pattern-facts.ts`。Arena runner 只在显式传入 `sceneStudy` 时增加同事实补充和可选提示，旧实验仍走原提示。RAG 继续使用原词项检索器，容量从 20 扩为 256；四组不引入不同分词、别名或排序。

每项模式返回规则版本、matched / not_matched / insufficient_data、事实引用、玩家与候选引用、研究问题和主题。缺失数据不补成零。候选状态与当前持牌状态分开；暗杠使七对子路线不适用。副露组数不计暗杠，加杠仍属于原来的一组。

## 18 个初始触发条件

以下是工程检索假设，不是最优打法规则。P01、P02、P05–P07、P13–P16 涉及候选状态，P03、P04、P18 使用当前持牌。

| ID | 条件 | 主题 |
|---|---|---|
| P01 | 无副露无杠，某弃牌后至少四种恰好两枚的对子 | 对子路线、七对子 |
| P02 | 无副露无杠，某候选七对子向听 ≤2 且 ≤一般形向听+1 | 七对子、牌效 |
| P03 | 当前暗手含役牌对子 | 役牌 |
| P04 | 当前暗手及自家副露中同色数牌 ≥8、其他数牌 ≤3 | 染手、牌效 |
| P05 | 两候选同向听，较多进张者保宝较少 | 牌效、宝牌 |
| P06 | 两个听牌候选的等待集合或未见枚数不同 | 等待 |
| P07 | 某听牌候选确认涉及振听 | 振听、等待 |
| P08 | 至少一家对手立直已受理 | 立直防守、押引 |
| P09 | 至少两家对手立直已受理 | 多家防守、安全牌 |
| P10 | 对手两组以上公开副露，或有公开役牌刻子、至少两枚公开宝牌 | 副露防守、押引 |
| P11 | 对手两组以上公开副露且数牌只涉及一色 | 染手、读牌、副露防守 |
| P12 | 他家最近舍牌在另一家立直受理后，且在该舍牌之前不是该立直家的现物 | 读牌、押引 |
| P13 | 面对立直，候选中共同现物牌种 ≤1 | 安全牌、多家防守 |
| P14 | 有听牌或一向听候选，同时 P08 或 P10 | 押引 |
| P15 | 对同一立直家，较快候选非现物、较慢候选为现物 | 安全牌、押引 |
| P16 | 剩余摸牌 ≤16，且有听牌或一向听候选 | 终盘、押引 |
| P17 | 半庄南四且四家点数完整 | 点况 |
| P18 | 当前自家保有宝牌 ≥2，同时 P08 或 P10 | 宝牌、押引 |

P15 先比较向听，再比较同向听下的进张。P06 比较集合而非数组顺序，未知未见枚数不会被当作相等。P12 复用现有现物判定，但先截断到观察舍牌之前，排除那张牌本身及后续河；非现物不等于危险，副露不等于听牌。提示保留全部命中，不以 Top-K 丢掉防守或点况；完整数值和引用在四组共同事实中。

## 教材与冻结

`scripts/scene-study/knowledge.json` 保存 40 张中文概括，每张 200–400 字；20 张 Beginner’s Luck 原始网页、20 张ネマタ《现代麻雀技术论》旧网页版。`cards.tsv` 是编辑源，`fetch-sources.py` 保存原始章节读取记录，`knowledge.mjs` 生成检索器兼容格式。卡片保留原题、章节路径、URL、HTML SHA-256、适用条件和例外。

这是网页版知识集，不代表新版书籍。两套教材的不同条件分别保留；邻近主题不删除。所有未核对牌图例题排除，因此首轮没有宣称完成任何牌图转码。a16 原文终盘押引公式后的不等号方向存在笔误，卡片明确指出并不复制数值阈值。卡片已逐章读取概括，尚需日麻评审确认其适用性，不宣称专家审核完成。

## 抽样与运行

CLI：`node bin/scene-pattern-study.mjs <命令> <试验目录> [参数]`。

1. `prepare <目录> <corpus.sqlite>`：只读公开语料库；使用同源归并后的完整牌谱身份隔离。当前来源为 nikke-tenhou，按日志规则标识限定四人南场。规则未知项保持未知，通过现有重放和合法动作校验后取样。
2. `freeze <目录> [专家设置JSON]`：固定数据、知识、处理代码、模型、参数与执行顺序。未提供文件时读取现有 Electron 专家设置；不存在则采用 Coach 已配置的默认 `gpt-6-luna / max`，记录来源。
3. `materials <目录>`：生成 `review/knowledge-needs-60.html`、JSON 模板和预选 48 局盲评材料；未生成的讲解明确标为空缺。
4. `run <目录> development 3`：小规模四组试跑。最多 12 个预选开发局面、累计最多 48 次尝试；预算校准前失败也计入累计上限。
5. `import-gold <目录> <人工标注JSON>`：必须在任何正式评测启动之前导入 60 局完整主题需求，冻结人工标注摘要。模板中的空值不能通过校验。
6. `run <目录> evaluation 60`：生成 240 份讲解。已有结果（包括失败）不会被覆盖或自动重试；进程异常后的 started 记录转成 interrupted。`recover <目录>` 仅在记录的进程已不存在时恢复锁和中断记录。
7. `materials <目录>`：更新匿名左右讲解，交给评审。`blind-key.private.json` 不应给评审，评审页不显示组别或模式列表。
8. `import-ratings <目录> <盲评JSON>`，然后 `report <目录>`：输出完整 JSON 指标与中文状态报告。

评审材料复用 `arena-console/case-view.mjs` 的 `observationView`、现有牌图与样式。四家公开场面同时展开，按局面翻页；候选事实可展开比较。可接受章节按两套教材分组为可搜索、多选的下拉表格，导出仍使用固定知识卡 ID。标注在当前浏览器保存草稿；页面与 `assets/tiles` 目录需一起保留。

### 自动标注预览（用户追加范围）

2026-10-23 用户指定先用 `gpt-6.1-sol / high` 自动标注 60 个评测局面。运行 `node scripts/scene-study/annotate.mjs <目录> 60 3`，最多三个独立模型上下文同时处理，复用 Arena 的隔离订阅适配器。模型只收到完整四家决策时公开场面、自己的手牌、确定性候选事实及全部 40 张知识卡；输入白名单排除模式命中、选择标签、模型讲解、实际结果与 Mortal 分数。

自动标注单独冻结模型、脚本摘要及输入摘要，逐局保留请求、结构化返回、用量与失败记录；已有记录不自动覆盖。`automatic-draft.json` 保留空的人工评审姓名与日期，不导入 `gold.json`。它用于页面预填和人工检查，不能称为人工金标准；正式 240 份生成与 48 局人工盲评仍未启动。每个主题附简短公开依据、把握程度、章节多选及知识缺口，未知与不适用分开。

自动标注结束后，可运行 `node scripts/scene-study/retry-annotations.mjs <目录> 1`（至多再有第 2 次补跑），仅对失败项补跑。先把对应失败及 started 记录完整移入 `automatic/retries/attempt-N`，模型、提示和输入保持不变；报告分别列首次失败数、补跑次数与当前完成数。`node scripts/scene-study/summarize-annotations.mjs <目录>` 生成自动标注预览摘要；再次运行 `materials` 即可预填页面。

自动标注的首个投影版本漏传顶层规则配置，已连同中断尝试保存在 `automatic-revisions/v1-missing-rule-config`；修正版也保留了赤牌弃牌身份、鸣牌来源、自家振听状态与摸牌来源。该修正不改变既有 18 个模式、正式四组模型或冻结样本。

开发预算校准命令为 `calibrate-budget <目录> <输出token上限>`，只允许预标注前且没有正式生成记录时使用。原冻结配置、失败、超时和中断均保存在 `calibration-history`，不能清除或重报为成功。首次试跑发现订阅模型报告的 output tokens 包含推理输出，2048 上限不足；统一改为每轮 32768，最终讲解仍要求约 400–700 字。四组参数一致，模型未更换。

120 开发局面来自至少 20 场，60 评测局面来自至少 10 场；每场至多 6 个，同一局同一自家座位至多一个。每个评测牌谱四个随机、两个挑战局面，挑战覆盖对子、威胁、组合主题和近阈值反例。盲评预选 32 随机+16 挑战。抽样不读取模型答案或 Mortal 分差；完整性筛选会排除许多缺失结算的历史记录，因此随机集也仅代表可通过现有校验、满足抽样配额的语料，不是所有对局的无偏样本。

## 四组与评价

| 组 | 完整局面及相同事实 | 模式 | RAG |
|---|---|---|---|
| A | 是 | 否 | 否 |
| B | 是 | 否 | 是 |
| C | 是 | 是 | 否 |
| D | 是 | 是 | 是 |

B、D 最多两次检索，每次至多三张、总计六张去重卡。LLM 可以不检索，不强制选章。模型上下文独立，执行顺序固定随机化。存储每次查询、实际返回、章节映射、时间、token 和全部失败；Mortal 本轮不运行、不充当专家标签。

预标注对所有主题区分必须、可选、不适用，并列可接受章节和库外缺口。模式精确率把必须与可选视为相关，召回只看必须主题。检索同时报告所有需求与库内需求召回、无关卡比例、无结果率；知识缺口、模式漏报与未查询可直接定位，查询/排序原因无法证明时保留待审，不伪造归因。

48 局盲评五项各 0–2 分，另记左右胜负、严重错误和实际覆盖主题。机械引用检查遍历所有生成结果，只证明引用确实来自实际返回卡，不能代替语义支持判断。A、C 的未人工评分输出不冒充专家评价。

按牌谱分组 bootstrap 2000 次，随机、挑战与合并结果分别报告。预定目标：模式精确率 ≥90%、必须主题召回 ≥85%；D–B 检索召回提高 ≥10 个百分点，或漏讲率相对下降 ≥20%；盲评胜多于负且严重错误不增。只有优势区间支持正向收益且质量达标，才可写本范围有效；否则至多值得扩大验证。D/B 平均 token 目标 ≤1.3，缺失 token 保持未知，不作零处理。

## 验证与治理

新增测试覆盖 18 个模式的正例、边界反例、资料不足；赤牌与四枚同牌；共同现物逐家计算；P12 历史时点；当前持牌与弃牌后状态；真实 mapper/replay 的未来信息与暗手隔离；同事实注入；检索限额、去重、无命中和伪造引用。

运行 build、typecheck、architecture、完整 Vitest，以及既有协议/语料回归。保留首次失败与后续复跑日志。Windows 全并发测试曾出现 Electron EBUSY、超时和测试进程 PID 竞态，使用原断言与原超时串行复跑；未放宽断言。新增 `.gitattributes` 固定带 hashbang 的语料 CLI 为 LF，解决 Windows checkout 后的 Vite 导入失败。试验脚本保留本轮冻结的源码字节，禁止 Git 自动转换 LF/CRLF，避免重新 checkout 后仅换行变化就使处理代码摘要失效。

检索无结果率按实际交给模型的去重卡片计算：重复查询仅返回已见卡片时，也记为本次没有新增结果。原查询、返回来源及去重记录保留，人工审查可区分词项无命中与重复查询；该指标不能单独代表底层检索器的词项命中率。

变更边界审查：contracts 增加数据契约；reasoning 复用事实投影与现物逻辑；desktop 增加可选离线入口；脚本持有样本、教材和试验档案。未建立新包、通用规则引擎、向量库、训练流程或生产开关。后续生产接入需另立任务。
